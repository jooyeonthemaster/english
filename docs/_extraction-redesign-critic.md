## C2 — 불완전(일부/기울어짐/잘림)

- **가장 잘 다룸: design-adaptive-surface.** 3단 게이트(카드 배지 → reviewing 배너 → 커밋 모달)를 가장 구체적으로 쓰고, "조용한 폐기를 명시 선택으로 승격"을 `build-payload.ts:35,61` 라인까지 짚었다. single-canvas도 동급(red 외곽 + WARN/CRITICAL severity). guided-wizard는 STEP5 게이트는 좋으나 "재촬영해 교체" 동선의 **실제 메커니즘**(교체 시 기존 segment·크레딧·잡 상태 어떻게 되나)이 비어 있다.
- **공통 빈틈 (날카롭게):**
  1. **"기울어짐(skew)"을 잘림과 한 배지로 뭉갰다.** skew는 크롭/재촬영이 아니라 **회전 보정(deskew)**이 답인데, 셋 다 회전 UI가 없다. guided-wizard는 `reasons:'skew'`를 타입에만 넣고 UI 인터랙션 부재.

  3. **"재촬영해 교체" 후 재정합.** 새 사진을 올리면 기존 plan의 해당 슬롯만 교체되는지, 전체 재트리아지인지 미정의(세 안 공통).
- **종합안 보강:** (a) skew 전용 회전 핸들/자동 deskew, (b) 잘림 판정을 트리아지+본추출 OCR confidence+종결부호 **2단 검출**(본추출 단계에서 한 번 더), (c) 단일 슬롯 교체 재촬영 플로우(잡 재커밋 안전성 코어 재사용 명시).

- **공통 빈틈 (D2 과금 정확성 — 프롬프트 명시 요구):**
  1. **크레딧 단가 표기 불일치.** wizard "−12 크레딧", adaptive/canvas "1 크레딧" — 셋이 제각각이고 **산정 기준**(지문당? 글자수? 변경수?)이 없다. "−12"와 "1"은 10배 차이. 사용자 신뢰 직결인데 셋 다 근거 미제시.
  2. **복원 실패 환불.** wizard/adaptive는 "실패 시 환불"을 말하나 canvas는 **"복원 결과 맘에 안 들면 폐기, 이미 쓴 크레딧 환불 안 됨"**으로 정반대 정책 — 즉 **실패 환불 vs 불만족 무환불의 경계**가 안에 따라 충돌. "성공했으나 품질 나쁨"의 과금이 가장 모호.
  3. **부분 채택 시 과금.** wizard만 [부분 수정 후 채택]이 있는데 부분 채택의 크레딧 처리 미정의.
  4. **복원 전 원문 보존.** adaptive "미적용 시 restoredText 저장하되 teacherText=rawText 유지" — 이 옵트인 보존 모델이 가장 안전, 나머지 둘은 복원 후 원문 복귀 시 데이터 상태 불명확.
- **종합안 보강:** 크레딧 산정 공식 단일화(지문당 고정 + 글자수 구간) + "실패=환불 / 성공품질불만=무환불(사전 고지)" 정책 명문화 + 부분채택 과금 규칙 + adaptive의 teacherText/restoredText 보존 모델 채택.

## C10 — 섞인 순서 업로드 (자동 재정렬)

- **가장 잘 다룸: 셋 다 얕음, design-adaptive-surface가 근소 우위.** 셋 다 "pageMeta 핑거프린트/페이지번호로 재정렬 제안 + 수동 드래그(`reorderSlots`)". adaptive만 "sourceFileName+페이지번호 OCR"로 감지 신호를 구체화. 하지만 셋 다 **재정렬을 거의 곁다리로** 처리.
- **공통 빈틈 (이게 가장 심각한 구멍):**
  1. **재정렬 ↔ 트리아지 순환 의존.** 트리아지가 경계/묶음을 추정하려면 **올바른 페이지 순서**가 전제인데, C10은 순서가 틀린 상태. 재정렬을 트리아지 **전에** 하나 후에 하나의 순서가 셋 다 미정의 — 후에 하면 트리아지 묶음 추정이 전부 무효화돼 재실행 필요(비용/지연 2배).
  2. **부분 재정렬·중복·누락 페이지.** 페이지 번호가 없는 자료(이미지 다발), 중복 스캔, 누락 페이지의 재정렬은 자동 불가 — 폴백 UI 없음.
  3. **재정렬 후 boundingBox/segment 인덱스 재매핑.** 슬롯 순서가 바뀌면 이미 만든 크롭/묶음의 페이지 참조가 깨지는데 재바인딩 스펙 부재.
- **종합안 보강:** 파이프라인 순서를 **재정렬 → 트리아지**로 고정(재정렬은 경량·OCR 페이지번호만), 번호 없는 자료는 수동 드래그 전용 + "순서 확신 못 함" 배너, 재정렬 시 segment/crop 페이지참조 자동 재바인딩 규칙.

## 횡단(cross-cutting) 요구 — 프롬프트가 명시했으나 세 안이 공통으로 빠뜨린 것

이게 진짜 "강박적 빈틈"의 핵심이다. 케이스별로는 어느 정도 다뤄졌지만, 아래는 **셋 다 약하거나 없다.**

1. **접근성(키보드/스크린리더) — 거의 전무.** canvas/adaptive의 핵심 인터랙션(드래그 크롭, 핸들로 경계 끌기, 이어붙이기 드래그)이 전부 마우스 전용. **키보드 대체 경로**(화살표키로 경계 이동, 숫자입력 좌표, Tab 포커스 순서)와 **스크린리더 라벨**(고스트 세그먼트/신뢰도/배지의 aria) 언급이 셋 다 없다. wizard가 스텝 구조라 그나마 키보드 친화적이나 명시 안 함. 메모리(`feedback_no_sparkles_icon`)는 아이콘 규칙만, 접근성은 미적용.

2. **모바일/태블릿 열화 — canvas가 자폭 인정, 나머지는 침묵.** single-canvas는 self-critique에서 "태블릿 정밀도 붕괴·핀치줌↔크롭 제스처 충돌"을 솔직히 인정(가장 정직). adaptive/wizard는 모바일 대응 **무언급**. 튜터가 모바일을 쓴다는 메모리(`project_tutor_mobile_activity_redesign`) 맥락에서 이건 큰 구멍. 모바일=리스트형 분할/병합 버튼식 폴백이 종합안 필수.

3. **복원 전후 diff 가시성 — 색상 규칙 충돌 위험.** 셋 다 diff를 빨강(제거)/초록 또는 밑줄로 표현. 그런데 메모리(`feedback_no_orange_icons`)는 주황 금지인데 **빨강/초록 diff는 명시 허용 여부 불명.** adaptive가 "취소선+slate/blue, 주황 금지"로 가장 조심스러우나, 색맹 접근성(색만으로 변경 구분) 미고려. 종합안은 색+기호(±) 병기 필요.

4. **automation bias(오추정에 권위 부여) — wizard만 자각.** guided-wizard가 "강사가 배너 안 읽고 [수락]만 누른다"를 정직하게 인정. 셋 다 트리아지 정확도(Flash 품질)가 곧 UX 신뢰자산인데, **저신뢰 구간(0.6~0.75)** UX가 가장 위험하다고 canvas/adaptive도 인정만 하고 해법 없음. 종합안: 저신뢰 시 자동경계 **제거**(고스트 안 그림) + "추정 안 함, 직접 확인" 강제 — wizard §4와 canvas §4의 폴백을 합쳐 표준화.

5. **트리아지 저신뢰 폴백의 일관성 — 셋이 다른 폴백 화면.** wizard=manualFallback 배너, canvas=1:1 기본 플랜, adaptive=Surface B 폴백. **폴백 목적지가 제각각** — 종합안은 단일 폴백("페이지=세그먼트 1:1 + 사후 정규식 위임 = 기존 동작 100% 동일")으로 통일. adaptive의 "기존 동작과 100% 동일(안전 회귀)" 표현이 가장 정확.

6. **크레딧 표기 정확성 — 전반 불일치(C9에서 지적한 것의 확장).** 트리아지 크레딧(wizard "무료/소액", 나머지 무언급), 추출 크레딧(adaptive만 "소비 예정 N" 푸터), 복원 크레딧(12 vs 1) — **3종 크레딧의 표기·확인·환불이 안마다 들쭉날쭉.** 종합안: 트리아지/추출/복원 3계정을 항상 분리 표기 + 각각 환불 정책 명문.

7. **묶음 경계 오판 시 교정 경로 — canvas만 완비.** 프롬프트가 "다중페이지 경계 오판 시 사용자 교정 경로"를 명시 요구. canvas만 체인 ✕로 해제, adaptive `[⛓ 끊기]` 있음, **wizard는 묶기만 있고 해제 UI 없음**(만든 묶음 되돌리기 부재 — 명백한 누락).

## 종합안 우선순위 (반드시 넣어야 할 보강 Top 8)

1. **D4 묶음의 멱등성/과금/lease 스펙** (C4·C5) — D1과 충돌하는 최대 리스크, 셋 다 봉합만 함.
2. **재정렬 → 트리아지 파이프라인 순서 고정 + segment 재바인딩** (C10) — 순환 의존, 셋 다 곁다리.
3. **promote 시 sourcePageIndex 매핑 로직 수정** (컬럼 추가만으론 손실 지속, 셋 다 누락).
4. **접근성 키보드/스크린리더 대체 경로** (횡단) — 셋 다 전무.
5. **모바일/태블릿 리스트형 폴백** (횡단) — canvas만 인정, 종합안 필수.
6. **크레딧 3계정(트리아지/추출/복원) 표기·산정공식·환불정책 통일** (C9·횡단) — 12 vs 1 충돌.
7. **C1 트리아지 스킵 빠른 경로 + auto-advance 임계=0.9·되돌리기 5초** (C1).
8. **skew 회전보정 + 잘림 2단 검출(트리아지+본추출 OCR confidence)** (C2) — skew가 잘림에 묻힘.

**관점별 채택 권고:** 인터랙션 정밀(C3 분할·C5 체인·C8 크롭·C4 해제)은 **single-canvas**, 입력유형별 형태/폴백/배치/크레딧표기(C1·C6·C7·C10·D3)는 **adaptive-surface**, 복원 diff 풍부함(C9)과 비개발자 의사결정 단순화는 **guided-wizard**. 종합안은 adaptive의 라우팅 골격 위에 canvas의 직접조작을 데스크톱 1급으로 얹고, 모바일은 wizard식 리스트 폴백으로 격하하는 하이브리드가 D1~D4를 가장 적게 위배한다.

## 4. 벤치가 찾아낸 결함과 수리

| 증상 | 근본 원인 | 수리 |
|---|---|---|
| 모니터·그래프에 "Cost Reduction: -80%", "10,000,000+" 같은 **지문에 없는 수치**가 찍힘 | 콘티 LLM이 그림 묘사 필드(action)에 따옴표 글자·수치를 썼고, 이미지 모델은 일반 규칙보다 그 명시 지시를 따랐다 | 세 겹으로 막았다. ① 검증기가 따옴표·%·큰 수치를 위반으로 잡아 수리 라운드로 돌린다(`VISUAL_TEXT_PATTERNS`). ② 컴파일러가 남은 조각을 제거한다(`sanitizeVisual`). ③ 레터링 규칙: 화면·문서·간판·도장·라벨·옷 글씨는 도형·아이콘만 허용한다 |
| KO_KEY 캡션이 "see the world in a distorted way**하게** 한다" 같은 혼종 문장이 됨 | 영어 동사구에 한국어 어미를 붙이는 것을 금지하지 않았다 | 계약에 좋은 예·나쁜 예를 넣었다. 검증기는 ① '-하게/-한다' 혼종 어미를 잡고 ② 캡션 속 영어가 지문에 글자 그대로 있는지 대조한다. KO_KEY 캡션 길이는 라틴 문자를 0.55폭으로 센다 |
| 긴 한 줄 캡션에서 한글이 깨짐(3건) | 긴 문자열일수록 글리프 오류가 늘어난다 | 컴파일러가 캡션·말풍선을 짧은 줄로 미리 끊어 줄마다 따로 인용한다(`wrapLettering`) → 깨진 문자열 0건 |
| 콘티의 cast 이름과 구도 설명 속 로마자 호칭이 달라 인물이 둘로 보일 위험 | 호칭 규칙이 없었다 | 콘티 프롬프트에 "cast.name 을 글자 그대로 쓴다"를 추가했다 |

## 5. 모델 한계 (쫓지 않기로 한 것)

- **행 높이·글자 크기 지시는 따르지 않는다.** 퍼센트 지시와 상대 지시("가장 높은 행, 1.5배") 모두 대체로 무시됐다. 글자 높이는 지시와 무관하게 약 17px(폭의 1/50)이다. A4 인쇄에서는 약 10.5pt라 충분히 읽히지만, 폰 폭으로 한 페이지를 통째로 볼 때는 작다. 미리보기의 확대·이동으로 대응한다.
- **한 음절 오탈자가 문자열의 약 4%에 남는다**(하콧길, 율렸다, 이결). 자막 편집기가 콘티 원문과 대조해 깨진 영역을 올바른 문구로 미리 바로잡아 둔다(`detect-lettering.ts`). 편집기에는 배포 전까지 상시 안내 띠가 뜬다.
- 치비·귀여운 화풍에서는 샷·앵글 차이가 평평해지는 경향이 있다(immune-cast 3/6).

## 6. 배포 순서 (필수)

1. **운영 ALTER** `scripts/sql/webtoon-storyboard.sql` — 26-09-30 적용 완료(`storyboard jsonb`).
2. **Trigger.dev 워커 배포** — 생성 로직(프로세서)은 Trigger 워커에서 돈다. Vercel만 배포하면 옛 프로세서가 새 모델 id를 AtlasCloud로 보내 전부 실패한다.
3. **Vercel 배포** (`vercel --prod`).
4. 운영 env 점검:
   - `WEBTOON_IMAGE_COST_USD`는 0 또는 미설정이어야 한다(양수면 원가 추정을 덮어쓴다).
   - `OPENROUTER_API_KEY`가 Vercel과 Trigger 양쪽에 있어야 한다.
   - `WEBTOON_IMAGE_MAX_ATTEMPTS`는 코드에서 2로 상한이 걸린다.

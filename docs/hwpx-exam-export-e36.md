## 2. 사용자가 신고한 것

### 2-1. 머릿글이 모든 쪽에 반복 → 표지 구역 신설
머리말 밴드(`hp:header applyPageType="BOTH"`)로 제목·학생정보를 얹어 한컴이 전 쪽에 반복했다.
**구역 3분할**로 재설계했다.

```
section0  표지    1단 · 머리말 없음 · 쪽번호 없음
section1  본문    N단 · 머리말 없음 · 쪽번호 1부터 재시작
section2  정답표  1단 전체폭 · 쪽번호 이어짐        (해설 포함 모드면 없음)
```

머리말은 이제 **어느 구역에도 없다**. 제목·학교/반/이름/시험일·안내문·학원 로고는 전부 표지로 갔다.
표지는 `cover.enabled` 와 무관하게 항상 나오고, enabled 는 **모양**(classic/band/minimal ·
eyebrow · footnote · 로고/정보박스 표시)만 좌우한다.

### 2-2. 학생정보 박스 오른쪽 잘림
| | 박스 우변 | "2학년" 끝 | 본문 우한계 |
|---|---|---|---|
| 전 | **570.7pt** | 569.9pt | 568.65pt |
| 후 | **568.4pt** | 568.0pt | 568.65pt |

원인은 산수였다. `emitTable` 은 셀 안쪽 폭을 `widthHpu − margins.left − margins.right` 로 잡는데,
안쪽 정보 박스를 **셀 폭 그대로** 만들면서 왼쪽 여백 200 HPU(= 정확히 2pt)를 빼지 않았다.
여백 상수를 한 곳(`LEFT_CELL_MARGINS`/`RIGHT_CELL_MARGINS`)에 묶어 재발을 막았다.

### 2-3. 정답표 "문항 / 정답" 2줄 터짐
2단 흐름 안에서 칸 폭(약 54pt)으로 그려서 터졌다. **1단 전체폭 별도 구역 + 밴드형**으로 재설계.

```
문항 │ 1 │ 2 │ 3 │ … │ 10        ← 라벨 셀 음영
정답 │ ⑤ │ ③ │ ⑤ │ … │ ②
```
열 폭은 항상 10칸 기준이라 마지막 부분 밴드(11~13)도 윗밴드와 열이 정확히 맞는다.
긴 정답(20자 초과)은 종전처럼 번호 목록으로 폴백한다.

### 2-4. 쪽당 2문제가 반영 안 됨
`layout.forceTwoPerPage` 가 HWPX 에 **전혀 전달되지 않았다**(타입에도 없었다).
한컴 2단 구역에서 `columnBreak` 가 동작한다는 걸 실험으로 확인하고, 미리보기
`paginateGroups` 의 규칙을 그대로 이식했다. 실측 결과 쪽당 정확히 2문제
(`문항수/쪽 = [2,2,2,2,2,2,1]`), 1단+쪽당1문제는 `[1×13]`.

같이 살아난 설정: 항목별 `breakBefore`(강제 쪽/단 나눔) · `keepWithPrev` ·
`pageNumberStyle`(가운데/바깥쪽/없음) · 학원 로고.

## 3. 파고들다 찾은 것 — 신고되지 않았던 결함

### 3-1. borderFill 참조가 통째로 한 칸씩 밀려 있었다 (근본 결함)

한컴이 직접 저장한 HWPX 를 뜯어보니 **`borderFill` 만 id 가 1부터** 시작하고
(`charPr`·`paraPr`·`style`·`tabPr`·`font` 는 전부 0부터) 본문도 `borderFillIDRef="1"` 을 쓴다.
한컴은 이 표를 id 속성이 아니라 **순서(1-based)** 로 읽는다.
우리는 0부터 뱉고 있었다 → **모든 테두리/음영 참조가 정확히 한 칸 앞으로 밀려 읽혔다.**

증상(오래 잠복):
- 학생정보 박스 라벨 셀의 옅은 음영(#F8FAFC)이 **아예 안 그려졌다**(색이 거의 흰색이라 아무도 몰랐다).
- 값 셀 테두리가 slate400 이 아니라 앞 항목의 검정으로 그려졌다.
- 표지에 검정 채움 막대를 넣자마자 그 검정이 한 칸 밀려 **정보 박스 전체가 새까맣게** 칠해지며 드러났다.

수리: 참조 기수를 `registerBorderFill` 한 곳에서 정하고(`index + 1`), 직렬화·하드코딩 참조를 전부 맞췄다.
off-by-one 을 가리려고 앞에 넣어둔 중복 "투명" 항목도 걷어냈다.

**부수 효과 — 오래된 미신 하나가 깨졌다.** 코드베이스 곳곳에 "부분 보더(윗변만) 표는 한컴이
옅은 파란 안내선 박스로 덧그린다"는 주석과 그걸 피하려는 설계가 있었다. 실험으로 확인하니
**부분 보더는 멀쩡했다**(오히려 네 변 동일 보더가 이중선이 된다). 정답표 위에 뜨던 파란 박스의
정체는 그 표의 참조가 한 칸 밀려 `slate400 + slate50 채움` 항목에 닿은 것이었다 — 즉 이 off-by-one.

### 3-2. 한컴의 들여쓰기 해석은 CSS 와 다르다
```
첫 줄       = leftMargin
이어지는 줄 = leftMargin + |indentFirst|
```
음수 `indentFirst` 가 첫 줄을 당기는 게 아니라 **이어지는 줄을 민다.** 2개 데이터포인트로 검증:

| leftMargin | indentFirst | 예측(첫줄/이어줄) | 실측 |
|---|---|---|---|
| 560 | −560 | 5.6 / 11.2pt | 5.7 / 11.2pt |
| 1700 | −1700 | 17 / 34pt | 17.1 / 34.0pt |

이걸 모른 채 `leftMargin: 560, indentFirst: -560` 을 쓰고 있어서, 선지 이어지는 줄이 본문
컬럼(16.9pt)이 아니라 11.2pt 에 서서 원문자 아래로 흘러내렸다. `leftMargin: 0` +
글자 크기 비례 매달림(`pt × 200`)으로 고쳤고, 같은 결함의 복제본 3곳(fragment 선지 2 + 정답표
긴 정답 목록)도 함께 수리했다.

### 3-3. 꼬리말 쪽번호가 아예 안 나왔다
`- / -` 로 비어 있었다. 인코딩 3종을 대조해 **`<hp:ctrl><hp:autoNum type="PAGE"/></hp:ctrl>`
형태만 렌더된다**는 걸 확인했다(ctrl 없이 쓰거나 `hp:pageNum` 은 공백).
`type="TOTAL_PAGE"` 는 한컴이 PAGE 와 똑같이 그려서(전 쪽이 `1/1, 2/2, 3/3…`) **`N / M` 표기는
원천적으로 불가** → 표기를 `- N -` 로 확정했다.

### 3-4. 검수 함대가 잡은 회귀·결함
| 건 | 판정 | 조치 |
|---|---|---|
| **문항 1개 내보내기에 빈 표지 1쪽이 붙음**(1쪽 → 2쪽) | 실제 회귀 | `includeCover` 플래그 추가, 해당 라우트에서 끔. 실측 1쪽 확인 |
| 학원 로고가 png 사전 변환에서 누락 → webp 로고 조용히 사라짐 | 사실 | 라우트에서 로고도 변환 |
| 지문 그룹 2번째 이후 문항의 `breakBefore` 유실 | 사실 | `idx > 0` 항목에도 명시 나눔 적용 |
| 1단 경로에서 강제배치 + stale breakPlan 충돌 | 사실 | 강제배치 모드는 breakPlan 을 비움(네이티브 경로와 동일 정책) |
| `firstPageHeaderPx = 0` 이 truthy 스프레드에 먹혀 유령 머리말 예약 | 사실 | `!== undefined` 로 교정(`contentSafetyPx` 도 같은 함정) |
| 다중빈칸 헤더가 선지 열과 1pt 어긋남 | 사실 | 매달림 폭을 호출자가 넘기게 변경 |
| 표지가 안 쓰는 꼬리말 7mm 예약 | 사실 | `marginFooter: mm(0)` |
| **구분선 블록이 부분 보더라 아티팩트** | **오탐** | 실험으로 반증(§3-1). 변경 없음 |

### 3-5. 정보 박스의 오른쪽·아래 변이 한글 편집 화면에서만 사라졌다

사용자 신고. 정보 박스를 가운데 정렬하려고 "테두리 없는 바깥 표"로 **감쌌더니**, 바깥 셀의
폭·높이가 안쪽 표와 정확히 같아져 마지막 두 변(x = 셀 폭, y = 셀 높이)이 셀 경계에 걸려
잘려 나갔다. 좌·상단 변은 좌표 0이라 살아남았다.

**PDF 내보내기는 클리핑 규칙이 달라 네 변이 멀쩡하게 나온다.** 그래서 PDF 기반 게이트는
7/7 을 통과하면서도 화면은 깨져 있었다 — 이 결함은 PDF 실측만으로는 잡히지 않는다.
재현·검증은 **한글 창을 직접 캡처**해서 했다(`c:/tmp/hwpx-verify/capture.ps1`).

수리: 중첩을 없애고 **표 하나**로 만들었다. 가운데 정렬은 좌우에 테두리 없는 여백 열을
붙여서 낸다. 같은 구조였던 제목 아래 강조 막대도 단일 표로 바꾸고, 중첩용 헬퍼
`centerTable` 자체를 삭제해 이 함정이 다시 생길 수 없게 했다.
(이 파일 상단 주석이 원래 "중첩 표 금지"라고 경고하고 있었는데 정작 그걸 어겼던 것이다.)

> **검증 교훈**: 한컴은 **편집 화면**과 **PDF 내보내기**의 렌더 결과가 다를 수 있다.
> 테두리·클리핑처럼 화면에서만 드러나는 것은 반드시 창 캡처로 확인해야 한다.

### 3-6. 해설 포함 모드에서 빈 쪽
해설이 붙으면 문항 하나가 칸보다 커져 자연 넘침이 일어나는데, 거기에 강제 단 나눔이 겹쳐
**꼬리말만 남은 백지 쪽**이 생겼다(9쪽 중 6쪽). 해설 모드에서는 강제 배치를 끄도록 했다
(코드가 이미 같은 이유로 breakPlan 을 비우고 있던 것과 동일 정책). 9쪽 → 7쪽, 빈 쪽 0.

## 4. 남은 것 (이번 범위 밖 — 판단 필요)

1. **정답표의 13번이 `④` 가 아니라 `4`** 로 나온다. `SUMMARY_COMPLETE_MC` 유형의 정답이 `"4"` 로
   저장돼 있고, 표기 함수 `formatStoredQuestionCorrectAnswer` 가 그대로 통과시킨다.
   **웹 미리보기도 똑같이 `4` 로 보여주므로 HWPX 결함이 아니다.** 다만 나머지가 전부 원문자라
   눈에 띈다. 고치려면 앱 전역이 쓰는 공용 함수를 건드려야 해서 손대지 않았다.
2. **DOCX 다운로드는 그대로다.** 표지·정답표·쪽당 N문제 모두 DOCX 에는 아직 없다. 요청이
   한컴 한정이라 범위를 넓히지 않았다.
3. **사문(死文) 표면**: `renderPageHeader`/`floatHeaderBlocks`, `SectionSpec.header`/
   `headerApplyFirstOnly`, env `HWPX_HDR_PX`/`HWPX_HDR_BAND_MM` 는 이제 프로덕션 호출자가 0이다.
   (`page-header.ts` 는 검증 하네스가 쓴다.) 삭제는 별도 정리 건으로 남겨 둔다.
4. **다운로드 메뉴의 `beta` 배지**를 뗄지 여부.

## 5. 재주행법

```bash
# 특정 시험지로 HWPX 생성 (설정 덮어쓰기 가능)
npx tsx .tmp-hwpx-e36/build.ts --exam "새 시험지 2026-08-22" \
  --out c:/tmp/hwpx-verify/x.hwpx --patch '{"layout":{"columns":1}}' [--answers]

bash .tmp-hwpx-e36/final-matrix.sh

python .tmp-hwpx-e36/gate.py <pdf> --title "새 시험지 2026-08-22" \
  --per-page 2 --answer-key [--no-page-numbers] [--render <dir>]

# 한글 "편집 화면" 캡처 — 테두리/클리핑은 PDF 로 안 잡힌다(§3-5). 표를 건드렸으면 필수.
#   주의: 이 스크립트는 한글 프로세스를 종료하므로, 이후 한컴 MCP 는 initialize_hwp 로 재연결한다.
powershell -ExecutionPolicy Bypass -File c:/tmp/hwpx-verify/capture.ps1 \
  -In <hwpx> -Out <png>

# 참조 테이블 id 기수 감사 (한컴 저장본과 대조)
node .tmp-hwpx-e36/id-audit.mjs <hwpx> ...
```

**음성 테스트**: 수리 전 산출물(`c:/tmp/hwpx-verify/base.pdf`)에 게이트를 걸면 반드시 **0/7** 이
나와야 한다. 7/7 이 나오면 게이트가 무뎌진 것이다.

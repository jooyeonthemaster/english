# OpenRouter 계정 정리 & 비용 분리 액션플랜

> **목적**: 하나의 OpenRouter 계정에 스모트 · AC'SCENT ID(온라인/오프라인) · 각종 외주 개발이 뒤섞여 있어,
> **어느 사업/프로젝트가 얼마를 쓰는지 재무적으로 분리**할 수 없는 상태다.
> 이 문서는 계정을 실제로 운영하는 개발자가 **그대로 따라 하면 정리가 끝나도록** 만든 실행 지침이다.
>
> **작성 기준일**: 2026-08-12
> **대상 계정**: OpenRouter `Personal` / `Default Workspace`
> **핵심 원칙 한 줄**: **"1 키 = 1 프로젝트 × 1 환경". 키는 절대 프로젝트 간에 공유하지 않는다.**

## 0. 왜 지금 정리해야 하는가 (30초 요약)

- 현재 키 **12개** 중 이름이 중복되거나(`smoat`×3, `acscentID`×2, `study`×2), 의미 없는 이름(`20260805`, `test`)이 많아 **누가 쓰는 키인지 대장으로 추적 불가**.
- 결정적으로, **`20260805` 키 하나를 두 주체가 공유**하고 있는 게 로그 분석으로 확인됨:
  - Gemini 3 Flash Preview 트래픽 → **AC'SCENT ID 온라인 사이트** (정상)
  - Gemini 3.6 Flash 트래픽(Vercel AI SDK, `ai/6.0.99`) → **정체불명 별도 도구/앱** (우리 코드에 없는 모델·SDK)

## 2. 목표 구조 (이렇게 정리한다)

### 2-1. 네이밍 규칙

```
{사업}-{표면/환경}[-{담당}]
```

- 소문자·하이픈만. 날짜·사람이름 단독 금지(`20260805`, `jaeyoung` 같은 이름 폐기).
- **사업(business unit)**: `smoat`, `acscent`, `contract`(외주), `internal`(사내도구)
- **표면/환경**: `prod`, `dev`, `online`, `offline`, `admin`, `ocr` 등
- **외주**는 반드시 클라이언트를 박는다: `contract-{클라이언트}-{프로젝트}`

**표준 키 세트 (목표)**

| 새 이름 | 용도 | 대체 대상(현재 키) |
|---------|------|--------------------|
| `smoat-prod` | 스모트 프로덕션 | #1 `smoat e80…356` (개명만) |
| `smoat-dev` | 스모트 로컬/개발 | (신규, 필요 시) |
| `acscent-online-prod` | AC'SCENT ID 온라인 사이트 | 🔴 #2에서 **신규 발급 후 이관** |
| `acscent-offline-prod` | AC'SCENT ID 오프라인(매장/키오스크) | #3 정체 확인 후 개명 or 신규 |
| `internal-tools` | Claude Code·Cline 등 사내 개발 도구 | #6 `claude code` 개명 |
| `contract-{클라이언트}-{프로젝트}` | 외주 건별 | #5 `jaeyoung`, #7 `aible` 정체 확인 후 |

### 2-2. 모든 키에 **예산 상한(Key limit)** 을 건다

- 현재 전 키가 `unlimited`. **유출/폭주 시 무제한 과금**된다 — 이게 재무 리스크의 핵심.
- 각 키 `⋮` → **Edit** → **Credit limit**에 월 예상치의 1.5~2배를 상한으로 설정.
- 예시: `smoat-prod` 월 $500 상한, `acscent-online-prod` $100, `contract-*` $50, `internal-tools` $20.
- 상한을 걸면 **정체불명 소비자가 붙어도 피해가 상한선에서 멈춘다.**

### 2-3. (선택) 재무 완전 분리가 필요하면 **Workspace 분리**

- OpenRouter는 **Workspace별로 크레딧 풀/청구를 분리**할 수 있다.
- 법인/사업부 회계를 완전히 갈라야 하면: `smoat` 워크스페이스 / `acscent` 워크스페이스 / `contract` 워크스페이스로 나누고 각자 크레딧을 충전.
- 다만 크레딧을 각 워크스페이스에 따로 넣어야 하므로 **자금 흐름이 복잡**해진다.
  → **1차 정리는 "단일 워크스페이스 + 키 분리 + 월별 배분"으로 충분**. 규모가 커지면 그때 워크스페이스로 승격.

## 3. 실행 액션플랜 (순서대로)

### STEP 0 — 백업 (5분)
- `Activity` → 기간을 **최근 3개월**로 놓고 `Explore`에서 **키별 사용액을 CSV로 export** (지금까지의 배분 기록 보존).
- 이 문서의 §1 대장 표를 스프레드시트로 복사.

### STEP 1 — 🔴 최우선: `20260805`(`b66…eda`) 분리·교체 (30분)
> 이 키가 **AC'SCENT 온라인 + 정체불명 도구** 공유 상태라 가장 위험하다. 끊어보면 정체도 드러난다.

1. `API Keys` → **+ New Key** → 이름 `acscent-online-prod` → **Credit limit $100** 설정 → 발급된 키 복사.
2. **AC'SCENT ID 온라인 사이트**의 환경변수(`OPENROUTER_API_KEY`)를 새 키로 교체 → 배포 → **AI 기능 1회 실행해 정상 동작 확인**.
3. 정상 확인되면 기존 `20260805` 키를 **Disable(비활성)** (삭제 아님, 관찰용).
4. **1~3일 관찰**:
   - 정체불명 Vercel AI SDK 트래픽이 "키 비활성"으로 에러 나면 → 그 도구 담당자가 연락 옴 = **정체 확인**. (팀원 도구였으면 `internal-tools` 또는 `contract-*`로 정식 발급)
   - 아무도 안 찾으면 → 유출 키였을 가능성 → 그대로 **완전 삭제**.
5. 관찰 끝나면 `20260805` **삭제**.

> ⚠️ **AC'SCENT 오프라인**도 이 키를 쓰고 있었는지 반드시 확인. 쓰고 있었다면 STEP 2를 함께 진행해야 서비스가 안 끊긴다.

## 4. 앞으로 지킬 규칙 (재발 방지)

1. **1 키 = 1 프로젝트 × 1 환경.** 절대 프로젝트 간 공유 금지. (공유하는 순간 오늘 같은 상황 재발)
2. **모든 키는 발급 즉시 네이밍 규칙 + Credit limit 설정.** `unlimited` 키 금지.
3. **키 이름에 날짜·사람이름 단독 사용 금지.** 사업·용도가 드러나야 함.
4. **외주 키는 `contract-{클라이언트}-` 접두사 필수**, 프로젝트 종료 시 즉시 삭제.
5. **키는 코드에 하드코딩 금지**, 항상 환경변수. (스모트는 준수 확인됨)
6. **분기 1회 미사용 키 청소** (`Last Used`가 오래된 키 검토).
7. **매월 1일: 키별 사용액을 export해 사업부에 원가 배분** (§5).

## 5. 매월 재무 배분 절차 (핵심 산출물)

정리가 끝나면, 매달 아래 3분 루틴으로 **사업부별 AI 원가**가 딱 떨어진다.

1. `Activity` → 기간을 **지난달**로 설정.
2. `Explore` → dimension을 **API Key**로 → **비용(spend)** 기준 정렬.
3. 키 이름이 곧 사업부이므로 그대로 표에 옮김:
   - `smoat-*` 합계 → 스모트 원가
   - `acscent-*` 합계 → AC'SCENT ID 원가(온/오프라인 분리)
   - `contract-*` → 외주 건별 원가 (클라이언트 청구 근거)
   - `internal-*` → 사내 R&D 비용
4. CSV로 저장 → 회계/정산에 첨부.

> **프로그램 자동화(선택)**: 계정에 이미 `OPENROUTER_MANAGEMENT_KEY`가 있으므로,
> Management/Provisioning 키로 Activity API를 호출하면 위 표를 **스크립트로 자동 생성**할 수 있다. (월별 배분 리포트 자동화)

## 6. 정체불명 키를 판별하는 방법 (운영자용 미니 가이드)

이름만으로 모르는 키를 만나면:

1. `Logs` → 그 키로 필터 → 요청 1건 클릭.
2. 오른쪽 **Generation details**에서:
   - **Model ID** → 어느 서비스 코드가 부르는 모델인지 대조 (예: `gemini-3-flash-preview` = AC'SCENT 온라인)
   - **user_agent** → `node`(순수 fetch, 자체 서버) vs `ai/x.x ai-sdk/...`(Vercel AI SDK 앱) vs `Cline/...`(IDE 에이전트) 구분
   - **http_referer / X-Title(App)** → 사이트 정체
3. 프롬프트 원문까지 봐야 하면 **I/O Logging을 잠깐 켜고** → 해당 서비스 1회 실행 → 새 로그의 프롬프트 확인 → **끝나면 반드시 다시 끈다**(개인정보/민감정보 저장 방지).

## 부록 A. 확정 사실 (검증 로그)

- `20260805`의 이원 사용은 AC'SCENT 개발 측 로그 분석으로 확인:

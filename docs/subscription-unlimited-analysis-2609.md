# 월간 구독(포트원) × 「월 5만원 무제한 + 동시 큐 5」 실측 검토

작성 2026-09-05 · 실측 원장: `credit_transactions`, `platform_api_usage_costs`, `workbench_ai_jobs`, `subscription_payments`
관련 정본: `docs/free-year-lockin-strategy-2609.md`(단위원가 §2), `docs/referral-system-audit-2609.md`(유통)

## 1. 결론 3줄

1. **포트원 월간 구독은 "가능"이 아니라 이미 다 구현돼 있다.** V2 빌링키 + 결제예약까지 1,345줄. 실적이 0건인 건 미완성이라서가 아니라 **PG 심사 범위에서 정기결제를 빼고 플래그(`NEXT_PUBLIC_SHOW_SUBSCRIPTION_BILLING=false`)로 꺼둔 것**이다(§2.3). **병목은 코드가 아니라 다날 정기결제 채널 심사다.**
2. **월 5만원 무제한은 원가로 안 망한다.** 학원-월 AI 원가 평균 6,600원 → 마진 87%. 풀링하면 꼬리 적자(최대 -10.9만원)는 흡수된다. **규모의 경제 측면에서 손해가 아니다.**
3. **단, 동시 큐 5개는 브레이크 역할을 못 한다.** 실측상 큐 5로도 시간당 596건이 통과해 손익분기(1,916건/월)를 **3.2시간이면 돌파**한다. 원가를 막는 건 큐가 아니라 **월 총량 캡**뿐이다. 게다가 현재 126곳 중 **39곳(31%)이 이미 동시 5 초과**라, 큐 5는 돈은 못 막고 UX만 깎는다.

## 2. 포트원 구독 — 구현 현황

### 2.1 이미 있는 것

| 층 | 실물 |
|---|---|
| SDK | `@portone/server-sdk` 0.19 (V2) · `@portone/browser-sdk` 0.1.8 |
| 발급 | `PortOne.requestIssueBillingKey` — `billingKeyMethod: "CARD"`, `offerPeriod: { interval: "30d" }`, `productType: "DIGITAL"` |
| 등록 | `POST /api/subscriptions/portone/register` → 빌링키 검증(status·storeId·issueId 대조) → `portone_billing_keys` upsert → 첫 결제 `payWithBillingKey` |
| 갱신 | `scheduleNextSubscriptionPayment` → `createPaymentSchedule(timeToPay)` — 성사 웹훅마다 다음 회차 재예약 |
| 해지 | `revokePaymentSchedules` + `deleteBillingKey` |
| 웹훅 | `/api/portone/webhook` (411줄, `portone_webhook_events` 멱등 처리) |
| 테이블 | `academy_subscriptions` · `portone_billing_keys` · `subscription_payments` |
| UI | 「카드 등록 및 첫 결제」 / 「자동갱신 ON·OFF」 (`subscription-billing-panel.tsx`) |
| 플랜 | STARTER 19,800/150 · **STANDARD 49,500/450** · PREMIUM 132,000/1,500 · ENTERPRISE 330,000/4,500 |

> **월 5만원 = 이미 존재하는 STANDARD 플랜 가격이다.** 신설이 아니라 이 플랜의 `monthlyCredits` 를 무제한으로 바꾸는 변경.

### 2.2 실적 (오늘 질의)

| 항목 | 값 |
|---|---|
| `subscription_payments` | **0건** |
| `portone_billing_keys` | **0건** |
| `academy_subscriptions` | TRIAL 234 · ACTIVE 13 — **ACTIVE 13곳 전부 `billingKeyId` NULL, `autoRenew` 0** |

→ ACTIVE 13곳은 수동 부여다. 정기결제 경로는 **한 번도 프로덕션에서 돌지 않았다.**

### 2.3 왜 0건인가 — 코드가 미완이라서가 아니다

`docs/portone-pg-switch-checklist.md` 가 원인을 확정한다. **구독 결제는 플래그로 꺼져 있다.**

```
NEXT_PUBLIC_SHOW_SUBSCRIPTION_BILLING=false        # .env.production.example
```

`FEATURE_FLAGS.SHOW_SUBSCRIPTION_BILLING` 이 가리는 표면 — 원장 콘솔 결제탭(`director/credits/page.tsx:233`), 관리자 플랜 화면(`admin/credit-plans`), 공개 상품·약관·개인정보·환불 페이지 4종.

이유는 **PG/카드사 심사 범위**다. 체크리스트 원문:

> - Payment method: credit card one-time payment only
> - **Subscription billing: excluded from the current PG/card review**
> - Public payment pages **must not mention subscription billing** while `NEXT_PUBLIC_SHOW_SUBSCRIPTION_BILLING=false`

즉 현행 다날 채널은 **"Danal general card payment channel"(일반 카드 단건)** 으로만 신청·심사됐고, 정기결제는 의도적으로 범위에서 뺐다. 공개 페이지에 구독을 노출하는 것 자체가 심사 조건 위반이다.

### 2.4 라이브까지 남은 것 — 병목은 코드가 아니라 심사다

1. **다날 정기결제(빌링키) 채널 추가 신청 + 카드사 심사** — 진짜 리드타임. 지금 채널로는 빌링키 발급이 안 된다.
2. **채널키 분리** — `getPortOneRuntimeConfig()` 는 채널키를 **하나만** 반환하고 빌링키 발급이 그걸 그대로 쓴다(`portone-subscriptions.ts:166`). 빌링 채널이 나오면 `PORTONE_BILLING_CHANNEL_KEY` 분리가 필요하다.
3. **플래그 해제 + 공개 페이지 문구** — 약관·환불·개인정보 4종에 정기결제 조항이 살아나야 하고, 이건 심사 통과 **이후**여야 한다.
4. **실패 회차 운영 경로** — `PAST_DUE` / `graceEndsAt` / 재시도는 코드에 있으나 미검증(결제 0건이므로 전 경로 미주행).

## 3. 「월 5만원 무제한」 손익

### 3.1 원가 (실측)

문항당 **26.1원**, 학습지 **118.6원** (`platform_api_usage_costs`, 1USD≈1,550원).

학원-월 AI 원가 분포(165 학원-월):

| 통계 | 원가 | 월 5만원 대비 |
|---|---|---|
| 평균 | 6,600원 | **+43,400 (마진 87%)** |
| p50 | 1,210원 | +48,790 (98%) |
| p90 | 10,470원 | +39,530 (79%) |
| p99 | 113,200원 | **-63,200 (적자)** |
| 최대 | 159,200원 | **-109,200 (적자)** |

**100곳 기준: 매출 500만원 vs 원가 66만원.** 상위 1%가 적자여도 전체는 압도적 흑자다. 보험과 같은 구조 — 꼬리는 풀링으로 흡수된다.

### 3.2 무제한 자연실험 (이미 했다)

무제한 크레딧(1,000,000)을 부여했던 학원들의 실제 월 원가:

| 학원 | 5월 | 6월 | 7월 | 8월 |
|---|---|---|---|---|
| A | $2.72 | $20.07 | $35.15 | $6.41 |
| B | $22.67 | $23.08 | — | — |
| C | $0.78 | **$102.00** | $17.47 | $2.47 |
| D | $2.10 | $2.06 | $1.11 | — |
| E | $2.28 | $15.93 | $0.06 | — |

→ **무제한을 줘도 헤비유저 상한은 월 $20~102(3~16만원).** 5만원 요금제에서 적자가 나는 구간은 **월 $32(약 5만원) 초과**이며, 표본 20건 중 3건(15%)이 여기 해당한다.

### 3.3 억제된 수요 주의

현 분포는 **크레딧 제약 하의 분포**다. 무제한이면 p50이 올라간다. 다만 §3.2의 무제한 코호트가 이미 그 상태의 실측이며, 거기서도 중앙값은 $2~20에 머물렀다.

**진짜 외생 리스크는 사용량이 아니라 모델 단가다.** 현행 gemini-3.7-flash는 **50% 프로모션 중**이며, 종료 시 문항당 26원 → **47~52원**. 모든 손익분기가 절반으로 줄어든다.

## 4. 동시 큐 5개 — 브레이크가 아니다

### 4.1 처리량 실측 (`workbench_ai_jobs`, 완료 잡)

- 문제 생성 1건: **p50 30.2초 · p90 54.5초**
- 큐 5 → **5 × 3600/30.2 = 시간당 596건**

| 항목 | 값 |
|---|---|
| 월 5만원 손익분기 | 50,000 ÷ 26.1 = **1,916건/월** |
| 큐 5로 도달 시간 | **3.2시간** |
| 프로모션 종료 시(52원) 분기점 | 962건 → **1.6시간** |
| 실측 최고 버스트 | 시간당 **498건** (서초골든타임 6/11 20시) |

→ **최고 헤비유저의 실제 버스트(498)조차 큐 5 상한(596)에 못 미친다.** 큐 5는 아무도 안 막는다. 한 달을 밀면 이론상 40만 건이 통과한다.

### 4.2 역효과 — 지금 사람들은 5보다 많이 쓴다

학원별 실제 최대 동시 실행 잡 수(126곳):

| 통계 | 값 |
|---|---|
| p50 | 5 |
| p90 | **12** |
| 최대 | **40** (1618학원) |
| 동시 5 초과 학원 | **39곳 / 126곳 (31%)** |

→ 큐 5를 걸면 **31%가 지금보다 느려진다.** 원가는 못 막고 체감 속도만 깎는 최악의 조합이다. 걸려면 **10~12**(현 p90 보존)이 하한선.

### 4.3 실제로 필요한 브레이크

큐가 아니라 **월 총량 fair-use 캡**이다. 실측 학원-월 소비 분포(174 학원-월): p50 75 · p90 839 · p95 1,776 · p99 4,208 · max 7,762 크레딧.

| 캡(문항) | 원가 | 5만원 대비 마진 | 걸리는 학원 |
|---|---|---|---|
| 1,000 | 26,100원 | 48% | 상위 ~3% |
| **1,500** | 39,150원 | **22%** | **상위 ~2%** |
| 2,000 | 52,200원 | -4% | 상위 ~1.5% |

→ **캡 1,500건이 정답.** p95(888건)의 1.7배라 **95% 이상은 체감상 진짜 무제한**이고, 꼬리만 막힌다. 프로모션 종료 시 **800~1,000건으로 내리는 회로차단기**를 미리 정의해둘 것.

## 5. 판단

**하라. 단 큐 5가 아니라 캡 1,500으로.**

- 원가는 감당된다(마진 87%). 규모의 경제 손해가 아니다.
- 진짜 값어치는 원가가 아니라 **리텐션**이다. 현재 크레딧제는 **"쓸수록 잔액이 준다"** 는 사용 억제 심리를 만든다. 사용 학원 133곳 중 82%가 1개월 이탈하는 상황에서, 무제한 구독은 사용량 → 습관 → 잔존으로 가는 유일한 구조 변경이다.
- **다만 이건 매출을 만들지 않는다.** 현재 결제 학원 4곳 × 5만원 = 20만원. 8월 실매출 745,800원보다 적다. 구독 전환은 **매출 구조를 바꾸는 것이지 매출 문제를 푸는 게 아니다.** 병목은 가격이 아니라 유통이라는 결론이 `free-year-lockin-strategy-2609.md`·`referral-system-audit-2609.md`와 세 번째로 일치한다.

### 선결 순서 (구현 전)

1. **다날 정기결제 채널 신청 + 카드사 심사** — 확정된 병목(§2.3~2.4). 코드 작업보다 먼저 걸어야 리드타임이 겹친다. 심사 통과 전에는 공개 페이지에 구독을 노출할 수 없다.
2. 무제한 전환 시 기존 충전 크레딧 잔액 처리(소멸·이월·환불) 정책.
3. 계정 다중 생성·경쟁사 정찰 등 남용 방어 — 무제한은 이 표면을 새로 연다.

## 6. 정기결제 추가 심사 — 절차·난이도·업계 실측 (26-09-05 조사)

> 출처: 포트원 공식 블로그·헬프센터, KG이니시스 법령 고지, 전자신문 26-04-13. **우리 케이스 확정은 포트원/다날 직접 문의가 정답** — 아래는 공개 자료 기반 사전 판단.

### 6.1 추가 심사는 필요하다 (단, 처음부터는 아니다)

정기결제(빌링)는 일반결제와 **별도 심사**다. 단건 카드결제 심사 통과분이 그대로 승계되지 않는다. 다만 사업자 실사 서류(사업자등록증·통장·인감·등기부)는 기존 다날 계약분이 살아 있으므로 **"결제수단 추가 신청"** 성격이며, 신규 입점보다 가볍다.

| 단계 | 소요 |
|---|---|
| 포트원 콘솔 전자결제(추가) 신청 승인 | 1~2영업일 |
| **카드사 심사** (카드사별 개별 진행) | **평균 2주** |
| 다날 계약~실서비스 오픈 | 7~10일 |
| **합계 현실선** | **약 2~4주** |

### 6.2 우리에게 유리한 조건

- **다날은 카드 빌링키를 지원**한다. PG 교체 불필요.
- **다날은 빌링키 발급 시 본인인증 생략이 가능**하다(사업자가 다날측에 요청). 나이스정보통신은 PC·모바일 모두 인증 필수라 전환율이 깎이는데, 우리는 그 함정을 피한다.
- **약관·환불·개인정보 페이지에 정기결제 조항이 이미 작성돼 있다.** 30일 갱신·빌링키 설명·해지 방법·일할 환불 산정 기준·7일 내 미사용 전액환불까지. `SUBSCRIPTION_BILLING_ENABLED` 플래그로 **가려져 있을 뿐**이라 심사 준비물 대부분이 완성 상태다.
- 요금제 4종이 DB에 있고 공개 요금표 렌더링 코드도 있다(`refund-policy/page.tsx:208`).

### 6.3 리스크 — SaaS는 "까다로운 업종"이다

포트원 공식 블로그가 명시한다: **SaaS는 "실체가 없다"는 이유로 리스크 업종으로 분류될 수 있다.** 제시된 통과 조건은 둘이다.

1. **로그인 없이 서비스 기능과 요금제를 누구나 알 수 있는 랜딩 페이지**
2. 환불 규정과 **정기결제 해지 방법**을 약관에 명확히 고지

→ ①이 우리 약점이다. 요금제가 플래그로 숨겨져 있고, 스모트는 소식·상당 표면이 로그인 전용이다(`sept-mock-free-distribution-2609` 참조). **심사 신청 전에 공개 요금제 표면을 먼저 열어야 한다.**

### 6.4 법령 의무 — 여신전문금융업법 시행령 (2021-11-18 시행)

여전법 시행령 §6-16, 감독규정 §24-14, 신용카드가맹점 표준약관. **미이행 시 가맹점이 소비자 손해배상 책임을 진다.**

| 의무 | 내용 | 우리 상태 |
|---|---|---|
| **사전 고지** | 정기결제 **금액 증가·유료전환 시 결제 7일 전까지** 거래내용·결제금액·변경일정·환불조건·해지사유 고지(서면·전화·이메일·메신저) | **없음 — 코드에 알림 경로 0** |
| **해지 채널** | 정규 영업시간 외에도 웹·앱·전화·메신저 중 **최소 1개**로 철회·해지 가능 | ✅ 콘솔 자동갱신 OFF (24h) |
| **일할 환불** | 이용일수 비례 공정 산정, 포인트·상품권으로만 제한 불가 | ⚠️ 약관에 산정 기준만 있고 자동화 없음(수동 처리) |

> **무제한 정책과 직결된다.** 「월 5만원 무제한」을 나중에 캡·요금 변경하면 **7일 전 사전 고지가 법적 의무**다. 무제한을 내걸기 전에 고지 경로부터 만들어야 한다.

포트원은 한 PG 반려 시 처음부터 다시 하던 구조를 **여러 PG 동시 비교·신청**으로 바꿨고, 기사는 이 개선이 *"정기결제, 구독, 디지털 콘텐츠처럼 **심사 기준이 까다로운 업종**에서 효과적"* 이라고 적는다.

→ **까다로운 업종인 건 사실이나, 통과가 예외적인 상황은 아니다.** 반려돼도 사유 보완 후 재심사 요청이 표준 절차이고, 다른 PG 병행 신청도 열려 있다(토스페이먼츠는 정기결제 요청 후 내부 심사, 나이스는 인증 필수라 차선).

### 6.6 권고 순서

1. **현행 단건 심사가 "완료"인지 확인** — 체크리스트가 심사 중 구독 언급을 금지하므로, 진행 중이면 6.3의 공개 노출과 충돌한다. (9월에도 충전 결제가 성사되므로 통과 상태로 보이나 확인 필요)
2. 다날에 **정기결제(빌링) 추가 신청** + **본인인증 생략 요청** 동시 접수.
3. 신청과 함께 **공개 요금제 페이지 노출**(플래그 ON) — 심사관이 로그인 없이 요금제를 봐야 한다.
4. **7일 전 사전 고지 경로 구현** — 법령 의무이자, 무제한→캡 전환의 전제.
5. 반려 시: 사유 확인 → 사이트 보완 → 재심사. 병행 PG 후보는 토스페이먼츠.

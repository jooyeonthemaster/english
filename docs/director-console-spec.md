## §1 문제 정의 (2026-07-20 사용자 피드백)

1. **폭 불일치**: 문제 생성(workbench)은 전폭인데 학생 관리 계열(학생 목록·학생 상세·과제 관리)은
   `PageShell max-w-[1600px]` 캡으로 좁아 보인다. 과제 상세 모달은 `max-w-[1100px]`로 더 좁다.
2. **모달 파편화**: 과제 종류(시험/학습지/문제 세트/어법 훈련)마다 볼 수 있는 것이 다르고
   (학습지만 학습 현황, 어법은 모니터링 탭 자체가 없음) 무엇을 할 수 있는지 계층이 안 보인다.
3. **워딩 모호**: "응시 이력" vs "시험 리포트"(내신 분석 건이 양쪽 중복 등장), "학습 현황"이
   서로 다른 3곳(학습지 매트릭스·튜터 모니터 nav·로스터 설명)에 재사용.
4. **실시간성 부재**: 학생 학습 이벤트가 유실되거나(파이프 결함 5종 — §5) 디렉터 화면이
   마운트 1회 스냅샷이라 실시간 반영이 안 된다.
5. **관제 축 부재**: 과제 단위 모니터링만 있고 **학생 단위** 학습 분석(어디서 어떻게 어려움을
   겪는지 누적·실시간)이 없다.

## §2 정보 계층 모델 (정본)

```
[제작 축 — 워크벤치]                 [관제 축 — 학생 관리]
 문제 생성 / 시험지 생성 / 학습지 생성      과제(StudyAssignment) = 배포 단위
 내신 시험 분석·리포트                     ├ kind: EXAM(시험) · WORKSHEET(학습지)
                                          │        · QUESTIONS(문제 세트) · GRAMMAR(어법 훈련)
                                          └ StudyAssignmentTask = 학생×과제 수행 단위

관제는 두 축을 가진다:
  ① 과제 축: "이 과제를 반이 어떻게 수행 중인가" → 과제 상세 모달 (§3)
  ② 학생 축: "이 학생이 전 영역에서 어디가 약한가" → 학생 상세 페이지 (§4)
두 축은 같은 데이터의 다른 절단면이다. 표면마다 데이터 소스가 달라선 안 된다.
```

어법 훈련은 **정해진 훈련 플로우**(드릴 커리큘럼)이고, 시험지·학습지·문제 세트는
**우리가 만든 콘텐츠의 과제화**다. 이 구분은 '과제 내용' 탭의 표현(출제 범위 vs 실물
미리보기)에서만 드러나고, 배정·진행·결과 분석의 **관제 골격은 4종 모두 동일**해야 한다.

## §3 과제 상세 모달 — 통합 계약

### 3.1 골격 (kind 불문 동일)

```
헤더: 아이콘+제목+kind 칩 · 요약 스트립(종류/상태/대상/마감/진행/평균 점수)
탭(항상 3개, 순서 고정):
  1) 배정 현황   — 학생별 태스크 테이블 + 배정·기한·재배포 액션
  2) 과제 내용   — EXAM·WORKSHEET·QUESTIONS: 실물 미리보기 / GRAMMAR 는 **탭 라벨
     자체를 "출제 범위"로** 표기(정본 확정 — 어법은 실물이 아니라 범위 스펙이므로
     라벨이 내용을 정확히 서술해야 한다. §2 의 "표현에서만 드러난다"는 이 라벨
     교체를 포함하는 뜻이다)
  3) 결과 분석   — kind별 내용 (아래 3.2). 탭 자체는 항상 존재한다.
푸터: 시작·마감 편집 / 종료·재개 / 복제 재배포 / 삭제
```

- 크기: `WideModal maxWidthClassName="max-w-[min(1500px,94vw)]"`. 본문 높이는
  `h-[min(78vh,900px)]` 고정 + **탭 콘텐츠 내부 스크롤** — 탭 전환 시 모달 높이가 출렁이지 않는다.
- 금지: kind에 따라 탭 개수가 달라지는 것(현행 문항 통계/학습 현황 조건부 노출). 결과 분석
  탭은 데이터가 없으면 "아직 기록이 없습니다" 빈 상태를 보여준다 — 탭을 숨기지 않는다.

### 3.2 결과 분석 탭 — kind별 내용

| kind | 내용 | 데이터 |
|---|---|---|
| EXAM | 문항 분석(기존 AssignmentQuestionStats). 학생별 점수·답안 검토(ReviewDrawer)의 정본 진입은 배정 현황 학생 행 — 결과 분석 탭에는 그 사실의 안내 한 줄만 둔다(중복 테이블 금지) | ExamSubmission |
| QUESTIONS | 문항 분석(기존). 행 확장 답안 대조의 정본 진입은 배정 현황 학생 행 — 동일하게 안내 한 줄 | 기존 |
| WORKSHEET | 학습 현황: 학생×스테이지 매트릭스(부분 진행 포함 — §5.3) + 반 취약점 4카드 + 학생 드릴다운 | worksheetStudyState/ItemLog |
| GRAMMAR | **훈련 현황(신설)**: 학생별 진행(푼 문항/전체)·정답률·최근 활동·훈련 기록 링크 | 기존 태스크 진행 + 어법 드릴 기록 |

### 3.3 실시간 규약

- 결과 분석 탭은 **15초 자동 폴링**(탭 비가시 시 중단, `document.visibilityState`) +
  마지막 갱신 시각 표기 + 수동 갱신 버튼.
- 학생 행에 **"지금 학습 중" 라이브 도트**: 해당 학생의 마지막 활동(state.updatedAt 등)이
  3분 이내면 펄스 도트 + "학습 중" 라벨.

## §4 학생 상세 페이지 — 탭 개편

### 4.1 탭 사전 (정본 — 라벨·순서·의미, 2026-07-21 v2)

**명명 원칙: 탭 이름 = 콘텐츠 도메인 명사.** "학습 분석/성적 분석"처럼 행위로 이름
붙이면 서로 구분이 안 된다(실사용 피드백). 탭은 세 묶음으로 나누고 묶음 사이에
얇은 구분선을 렌더한다:

```
[제작 콘텐츠 — 선생님이 만든 것]   [내장 프로그램]   [운영]
 개요 · 학습지 · 시험 · 내신 리포트 ‖ 어법 훈련      ‖ 과제 · 출결 · 수납 · 상담 · 학부모
```

| 순서 | 라벨(정본) | key(불변) | 의미(한 줄 설명 — 탭 콘텐츠 상단에 상시 노출) |
|---|---|---|---|
| 1 | 개요 | overview | 전 영역 요약 |
| 2 | **학습지** | study | 배포한 학습지의 단계별 학습 기록·취약점 — 실시간 (§4.2) |
| 3 | **시험** | exams | 배포한 시험지 응시와 내신 시험 분석 점수를 한 시계열로 |
| 4 | 어법 훈련 ‖ | grammar | 스모트 내장 어법 커리큘럼의 훈련 기록·개념별 정오 |
| 5 | 과제 ‖ | tasks | 배포된 모든 과제의 수행 상태 |
| 6~ | 출결 · 수납 · 상담 · 학부모 | 동일 | 동일 |

- **리포트는 시험 탭 내부 세그먼트다** (`성적 분석 | 리포트 N`) — 리포트는 시험
  도메인의 산출물이지 독립 도메인이 아니다(2026-07-21 사용자 확정: "내신 리포트가
  아니더라도 시험에 대한 리포트일 수 있다"). 같은 내신 분석 건이 두 탭에 중복
  등장하던 문제도 함께 해소. 세그먼트 활성 시 설명 스트립 문구가 "시험 분석·상담
  리포트 문서 관리(채점·공유·인쇄)" 로 바뀐다. 구 딥링크 `?tab=reports` 는 시험
  탭 리포트 세그먼트로 별칭 해석(복귀 링크 호환을 위해 URL 표기도 유지).
- 근거: 학습지·시험지는 **선생님이 직접 만든 콘텐츠**의 기록이고, 어법 훈련은
  **스모트 자체 커리큘럼**이다 — 이 존재론적 차이를 탭 묶음이 표현해야 한다.
- (개정 이력: v1 "학습 분석"→"학습지", "성적 분석"→"시험", v2.1 "내신 리포트" 탭
  → 시험 탭 세그먼트 흡수. key 는 불변이라 딥링크 호환 유지.)
- nav-config의 튜터 모니터 라벨 "학습 현황" → **"실시간 모니터"** (라벨 충돌 §1-3 해소).

### 4.2 학습 분석 탭 (신설 — 학생 축 관제의 본체)

와이드 2열 그리드(<lg 1열). 각 카드 고정 높이 + 내부 스크롤. 15초 자동 폴링.

```
┌ 실시간 학습 피드 ──────────────┐ ┌ 영역별 숙달도 ─────────────────┐
│ 최근 문항 로그 타임라인          │ │ 어휘/직독직해/어법/빈칸/어순/    │
│ (시각·과제·단계·문항·정오·답)    │ │ 영작/독해 — 첫 시도 정답률 바    │
│ "지금 학습 중" 상태 헤더         │ │ (누적, 전체 학습지)             │
├ 누적 취약 단어 ────────────────┤ ├ 취약 문장·어법 포인트 ──────────┤
│ 오답 단어 Top + 이력(드로어 재사용)│ │ 문장별/어법 코드별 오답률 순위    │
├ 학습지별 진행 매트릭스 ─────────┴─┴────────────────────────────────┤
│ 과제(행) × 스테이지(열) — 과제 축 매트릭스의 전치. 부분 진행 표기 포함  │
└──────────────────────────────────────────────────────────────────┘
```

- 데이터: 신규 서버 액션 `getStudentStudyAnalytics(studentId)` — 학생 스코프
  worksheetStudyState/ItemLog 전량 집계(스킬별·문장별·어법코드별·과제별). 어휘 상세는
  기존 `getStudentWeakWords` 재사용.
- 빈 상태: 학습지 스터디 기록이 0이면 안내("학습지 과제를 배포하면 학생의 단계별 학습
  기록이 여기에 실시간으로 쌓입니다") + 과제 배포 CTA.

#### 4.2.1 지문(학습지) 필터 — 탭 전역 스코프 (2026-07-20 확정)

**필터는 피드만 거는 게 아니라 탭 전체의 스코프다.** 이 탭의 존재 이유가 "이 학생이
**어느 지문에서** 어디에 취약한가"이므로, 지문을 고르면 숙달도·취약 단어·취약 문장·
어법 포인트가 전부 그 지문 기준으로 다시 계산돼야 한다.

- 위치: 탭 헤더 바로 아래 단일 행. `학습지` 라벨 + 칩 리스트(가로 스크롤, 줄바꿈 금지).
- 칩 순서: **최근 활동 내림차순**(매트릭스 행 순서와 동일 — 두 표면의 순서가 어긋나면 안 된다).
  첫 칩은 항상 `전체`. 제목은 `max-w` 로 자르고 `title` 속성에 원문.
- 각 칩에 그 지문의 **첫 시도 오답 수** 배지(0이면 미표시) — 어디를 봐야 할지가 칩에서 보인다.
- 학습 기록이 있는 학습지가 1개뿐이어도 필터 행은 렌더한다 — "지금 어느 범위를 보고
  있는가"가 항상 보여야 하고, 숨기면 기능 자체가 없는 것으로 오인된다(실사용 피드백).
  기록이 0건이면(학습지 없음) 렌더하지 않는다.
- 선택 시 카드 aside 문구가 `전체 학습지 누적` → `이 학습지 기준` 으로 바뀐다(스코프 오독 방지).
- 선택한 학습지가 폴링 갱신에서 사라지면(과제 삭제) 자동으로 `전체` 로 되돌린다.
- **매트릭스 행 클릭 = 그 지문으로 필터**(토글). 선택 행은 하이라이트 + `aria-pressed`.

#### 4.2.2 실시간 학습 피드 — 노이즈 압축·보조 필터·문항 상세

- **보조 필터**(피드 헤더): `전체 / 채점 / 오답` 세그먼트 + 각 건수. 기본 `전체`.
- **무판정 연속 압축**: 통독·카드처럼 정오 판정이 없는 로그가 같은 단계에서 연달아 2건
  이상이면 한 줄로 접는다 — `지문 통독 확인 완료 ×6 · 17:27~17:50`. 클릭하면 인라인 펼침
  (데이터를 숨기는 게 아니라 접는 것 — 전수는 항상 열람 가능해야 한다).
- **문항 행 클릭 → 중앙 팝업**(WideModal, max-w 1180px — 우측 시트 금지, 2026-07-21
  사용자 확정). 좌측 열에는 **학생이 본 문항 원형을 그대로 임베드** — 서버가 같은
  taskId 시드로 재컴파일해 복원한다(getStudyItemPreview; 컴파일러가 결정론이라 선지
  순서·디코이까지 동일). 렌더는 디렉터면 읽기전용 뷰(study-item-preview-view, 전
  11유형)로 하되 지시문 문구는 학생면 ItemInstruction 과 동일하게, 정답·학생 답을
  태그로 겹쳐 표기. 학습지 편집으로 문항이 사라졌으면 안내, planHash 가 다르면
  "수정되어 다를 수 있음" 배지. 우측 열: 정오·학습지·단계·영역·시각(초)·시도·소요·
  힌트·학생 답·단어와 뜻·문장 번호·어법 포인트 + **같은 단어(없으면 같은 문항)의
  최근 기록 타임라인**. 푸터 CTA `이 학습지만 보기`.
- 피드 이벤트 조회 상한은 서버 상수(현행 200건). 상한에 걸리면 카드 하단에
  "최근 N건 기준" 을 표기한다 — 조용한 절단 금지.

## §5 무손실 실시간 이벤트 파이프 (WS-spec §7 개정의 요약 — 정본은 WS-spec)

### 5.1 확정된 결함 5종 (2026-07-20 실측)

1. planHash 드리프트 시 409 → 클라가 이벤트 폐기(**배포마다 진행 중 세션 답안 전량 유실** — 실측 재현).
2. FLUSH_THRESHOLD=5 — 5문항 미만 버퍼는 영영 미전송.
3. SPA 라우트 이탈 시 언마운트 플러시 없음(pagehide는 SPA 내비에서 안 뜸).
4. stageDone 플러시 실패 시 재시도 없음 + 동시 플러시 때 조용히 드롭.
5. 디렉터 학습 현황 탭이 마운트 1회 스냅샷(폴링·갱신 없음).

### 5.2 새 계약 — "이벤트는 절대 거절하지 않는다"

- 서버는 planHash 불일치로 **이벤트를 거절하지 않는다**. 로그 append·스테이지 병합·취약점
  누적은 항상 수행한다(stageId 카탈로그는 코드 버전 간 안정). 응답에 `planStale: true`를
  실어 클라가 부드러운 안내만 하게 한다(기록은 계속 저장됨을 명시).
- 클라: 채점 판정은 **문항마다 즉시 플러시**, 무채점 전진은 1.2초 디바운스. stageDone은
  ref 로 보관해 성공 응답까지 재시도(4초 백오프). 동시 플러시는 드롭이 아니라 큐잉.
  언마운트 시 keepalive 플러시. 버퍼는 localStorage 에 미러링해 탭 크래시도 복원.
- 클라 요청에 `progress: { answered, total, firstCorrect, firstTotal }` 동봉 → 서버가
  in-progress 스테이지 상태에 저장 → 디렉터 매트릭스가 "진행 3/12 · 정답 2" 표기 가능.

### 5.3 디렉터 표기

- 매트릭스 셀: todo `—` / in-progress `진행 n/m`(정답 수 툴팁) / done 점수%.
- 부분 진행의 오답 단어·문장·어법 집계는 이미 로그 기반(status 필터 없음)이므로 그대로 산다.

## §6 레이아웃·타이포 규범

- **PageShell 전폭화**: `max-w-[1600px]` → `max-w-none`(전폭). 워크벤치 전폭 페이지와 통일.
  소비처 전수 감사: 그리드가 캡 전제로 짜인 곳은 `xl:grid-cols-N` 상향으로 대응(축소 금지).
- 학생 상세 헤더 확대: 아바타 `size-14`→`size-16`, 이름 `text-xl`→`text-2xl`, 통계 스트립
  수치 `text-lg`→`text-2xl`·패딩 상향. 메타 행 `text-[12.5px]`→`text-[13.5px]`.
- 밀도 규범: 디렉터 관제 표면의 본문 최소 `13px`, 보조 `12px` 미만 금지(10~11px 칩 제외).
- 섹션 높이 정합: 나란한 카드는 `h-[Npx]` 또는 grid row 고정 + 내부 `overflow-y-auto`.
  페이지가 옆으로 출렁이는 것 금지(`overflow-x` 는 컨테이너 내부 스크롤로).

## §7 무회귀 계약

1. **이 개편에서의** 데이터 스키마 변경 없음(stageStates 는 Json — additive 필드만).
   `wordMeaning` 컬럼·인덱스는 선행 작업(누적 취약 단어장, 2026-07-20 오전)의 것으로
   수동 SQL 이 로컬 DB 에 이미 적용됨 — 프로덕션 배포 시 같은 SQL 실행 필요.
2. 학생(/g) 표면의 시각 결과물은 **이 개편의** 대상이 아니다(플러시 로직만 변경,
   staleNotice 문구만 §5.2 로 교체). 단, 선행 작업으로 이미 추가된 학생 표면
   (/g/vocab 취약 단어장·g-shell 메뉴 항목·스터디 허브 등)은 사용자 명시 요구의
   산물로 이 조항의 위반이 아니다.
3. 기존 딥링크(`?open=`, `?tab=exams` 등) 는 신 탭 key 로 리다이렉트 매핑(구 key 허용).
4. 과제 상세 모달의 기존 기능(재배포·리마인드·기한 편집·삭제·복제) 전부 보존.
5. PageShell 소비처 중 관제 외 페이지가 있으면 폭 변경의 영향 전수 확인.

## 3. 시그니처 함정 — 층별 출제 장치

### 3-1. 전 층 공통 — 축 분산 프레이밍

**정답 포인트와 같은 미끼를 0개로 둬서 학생이 그 축을 한 번도 예열하지 못하게 한다.**

| 층 | 미끼 4개가 전부 정답과 다른 축인 비율 |
|---|---|
| 기본 | 84.6% (44/52) |
| 중급 | **89.0%** (73/82) |
| 킬러 | 82.4% (42/51) |

특히 **정답이 a(정동사 결손)일 때 b(관계사) 미끼를 깔아** "이 문항은 관계사 문항"이라는 프레임을 심는다 — 킬러에서 정답 a 14건 중 **12건**에 b 미끼가 들어 있다.

반대로 **정답이 b 인 15건 중 13건은 미끼에 b 가 아예 없어** "관계사는 안 나오는 문항"처럼 보이게 한다.

### 3-2. 전 층 공통 — 정오 쌍둥이 예열 (legal-twin priming)

**정답과 같은 통사 표면의 「옳은 버전」을 먼저 보여줘서 "이 구조는 이미 확인했다"고 믿게 만든다.**

| 층 | 관측 |
|---|---|
| 기본 | 12건 / 55 (21.8%) |
| 중급 | 최소 12건 |
| 킬러 | **최소 18건 / 51 (35.3%)** |

세 갈래 —
1. **동일 표면 정오 짝**: `was asked` + 목적어 잔류(정문) vs `was demanded` + 목적어 잔류(오류)
2. **동일 수법 반복**: ① 삽입 뒤 정상 본동사(정문) → ② 삽입 뒤 분사(오류)
3. **밑줄 없는 대조군**: 같은 문장 안의 옳은 `what`, 바로 앞 절의 정상 `that`

### 3-3. 중급·킬러 — 결손형 (「없는 단어」를 찾게 하기)

**틀린 형태를 넣는 게 아니라 옳은 토큰을 지운다.** 전치사+관계대명사에서 전치사만 삭제(`in which` → `which`), to부정사에서 `to` 삭제, 수동태에서 `be` 삭제.

- 중급 **10건** (전치사 삭제 6 · to 삭제 2 · be 삭제 1 · 문미 전치사 삭제 1)
- 킬러 **6건** — 그중 3건이 **2024~2026에 집중(최근 강화 추세)**

> "오형태 토큰이 없으므로 형태 스캔에 걸리지 않고, 결손 지점이 밑줄 경계 바깥(왼쪽)인 경우가 많아 밑줄만 보면 영구히 안 보인다."

### 3-4. 킬러 — 밑줄 무흔적

**정답 밑줄 조각만 떼어 읽으면 오류 흔적이 0이다.** 위반은 밑줄 왼쪽의 병렬 앵커, 오른쪽의 본동사, 절 경계 너머의 조동사와 대조해야만 성립한다.

킬러 최소 11건. 출제자는 **미끼를 전부 「밑줄 안에서 판정이 끝나는」 유형으로 깔아 잘못된 판정 습관을 4번 강화한 뒤** 정답에 도달시킨다.

### 3-5. 킬러 — 역함정 (정확한 지식이 오답을 지지)

**암기한 규칙이 정답 자리를 「무죄」로, 미끼 자리를 「유죄」로 판정하게 배치한다.** 킬러 최소 8건.

- `make + 원형` → 진짜는 가주어 뒤 진목적어 to부정사
- 「수동태 뒤 목적어가 있으면 오류」 → 4형식 수동이라 정상
- 「목적어 없으면 수동」 → 목적어가 절 머리로 빠졌을 뿐
- `be used to + v-ing` → 해당 자리는 `be used to-v`라 정문

> **규칙을 잘 아는 학생일수록 오답으로 끌려간다.**

### 3-6. 기본 — 난도 역전 배치 / 스캔 피로 지점

- **난도 역전**(6건): 정답은 1스텝에 끝나는 가장 싼 자리, 미끼에는 주어-동사 22단어 분리·선행사 3중 후보 같은 무거운 판정. "어려워 보이는 쪽이 정답"이라는 메타 추론을 역이용.
- **스캔 피로 지점**(10건, 18.2%): 정답을 마지막 문장·마지막 밑줄에 두고, 첫 밑줄에는 `where`·측정 단위 수일치 같은 최상위 함정 카드를 깔아 초입에서 시간을 태운다.

### 3-7. 중급·킬러 — 가짜 정동사 (a형 은폐)

정답이 a일 때 **반드시** 동반된다(킬러 정답 a 14건 전부).
1. 주어와 본동사 자리 사이에 관계절·삽입구를 끼워 그 안의 동사를 본동사로 착각시킴
2. 과거형·과거분사 동형(`used`/`inhabited`/`observed`)을 후치수식 자리에 놓아 본동사로 오독시킴
3. 지문 곳곳에 정상 `-ing`를 깔아 -ing 경보를 무디게 함

### 왜 그렇게 되었나 — 다양성 요구의 역효과

프롬프트가 요구하는 "서로 다른 코드 4개 이상"은 **잘 지켜지고 있다**(3종 미만 위반 0건, 5종이 78%).
그런데 최빈 코드 조합이 `b·c·d·e·f`(4건) · `b·c·d·f·g`(3건) · `b·c·d·f·h`(2건) — **상위 조합 전부에 f 가 있고 a 는 8개 중 2개에만** 있다.

**"다양하게 채워라"라는 요구가 모델을 만들기 쉬운 f·g·k 로 밀어낸다.** 다양성 규칙 자체가 죽은 미끼를 유도한다.

## 5. 처방

### P1. 미끼 풀을 코드 개수가 아니라 **허용 목록**으로 준다 — 최우선

```
현재: "서로 다른 코드 4개 이상"      → 모델이 f·g·k 로 칸을 채움
개선: "미끼는 a·i·b·c·e·h 에서 4개"  → 죽는 코드가 애초에 풀에 없음
```
근거: dead율 a 0% · i 0% · b 5% · e 6% · c 10% · h 12% vs f 77% · g 65% · k 62%.
f·g·k 는 **한 문항에 합쳐 1개 이하**로 상한.

### P2. 정답 포인트를 난이도별 기출 분포에 맞춘다

| | 1순위 | 2순위 |
|---|---|---|
| 기본 | b 관계사 21.8% · d 수일치 21.8% | a 20.0% |
| 중급 | **a 정준동사 32.9%** | b 17.1% · c 13.4% |
| 킬러 | **b 관계사 29.4%** · a 27.5% | d 13.7% |

현재 생성기는 전 난이도에서 d 39% / b 29% / a 12% 로 **고정**돼 있다.

### P3. 난이도를 「문법 항목」이 아니라 「단서 거리」로 정의한다

프롬프트의 난이도 지시를 이렇게 바꾼다:

| 난이도 | 지시 |
|---|---|
| 기본 | 판정 단서를 **밑줄 안 또는 같은 절 안**에 둔다(기출 81.8%). cross-sentence 금지 |
| 중급 | **cross-clause 를 3분의 1**로(기출 31.7%). 삽입절을 걷어내야 주어가 드러나게 |
| 킬러 | **밑줄 조각만 보면 정문**이어야 한다. 판정 단서를 밑줄 밖 병렬 앵커·본동사·절 경계 너머에 둔다 |

### P4. 함정 장치를 명시적으로 주문한다 (금지가 아니라 지시)

1. **축 분산**: 미끼 4개에 정답 포인트를 **넣지 마라**(기출 82~89%). 특히 정답이 a면 b 미끼를 깔아라
2. **정오 쌍둥이**: 정답과 같은 통사 표면의 **옳은 용례**를 정답보다 앞 밑줄이나 밑줄 밖에 하나 심어라(기출 22~35%)
3. **결손형**(중급·킬러): 틀린 형태를 넣지 말고 **옳은 토큰을 지워라** — `in which`→`which`, `to` 삭제, `be` 삭제
4. **가짜 정동사**(정답 a일 때 필수): 주어와 밑줄 사이 삽입절 안에 동사를 두어 "동사는 이미 나왔다"는 착시를 만들어라

### P5. 밑줄 배치를 서버 계산으로 회수 (검증 완료, 실행은 후순위)

문장 단위 슬롯을 서버가 계산해 주입하면 **「한 문장에 밑줄 2개」(현재 46%)가 구조적으로 0%가 된다.**

실사용 지문 32편 역검증:

| | 기출 | 할당기 | 현재 LLM |
|---|---|---|---|
| 한 문장 밑줄 2개+ | 10% | **0%** | 46% |
| 분산도 | 57% | 64% | 58% |
| 첫 문장 밑줄 | 0.52 | 0.09 | 0.98 |

기출 자리 재현율 83%(대조군 73%). 근거: 기출 밑줄 문장은 평균 22.5단어 vs 비밑줄 16.8단어이고, 길이 1~5위 문장 적중률 60~75%·6위부터 42%로 급락.

**미해결 리스크**: 슬롯에 문법 포인트가 없으면 모델이 억지 포인트를 만들 수 있다(문제가 배치 → 포인트로 이동). LLM 순응 여부도 미검증. 실제 생성 A/B 필요.
**미세조정**: 첫 문장을 후보에서 빼지 말고 **정답 슬롯에서만** 제외해야 기출(0.52)에 맞는다.

### P6. 지문 입력 검증 (게이트 아님)

어법 지문 규격은 **130~180단어 / 6~8문장**(기출 실측). 실사용 32편 중 2편이 **89문장 1,289단어 · 87문장 1,156단어** 교과서 덤프였다.
10문장 초과 시 **연속 7문장 창** 자르기 — 5편 실측에서 분산도 19% → 71%.
※ 실사용 지문 중앙값은 7문장으로 기출과 같다. **길이 문제는 일반적이 아니라 이상치 6%의 문제다.**

### P7. 게이트 확장은 보류, 반려 게이트는 기각

어법 게이트 5종이 `if (opts?.grammarKillerV2)` 안에만 있어 중급은 무방비다([md-stream/route.ts:531](../src/app/api/workbench/ai-jobs/question-generation/md-stream/route.ts#L531)).
다만 **구조 위반을 반려로 잡는 안은 실측으로 기각됐다** — 단일·복합 조건 16종을 스윕했으나 「기출 오반려 ≤3% + 검출 ≥30%」를 만족하는 임계가 없다. 생성물 위반이 "심한 소수"가 아니라 "얕고 광범위"(42%가 신호 1개)하기 때문이다. 상세는 스펙 §3-0.

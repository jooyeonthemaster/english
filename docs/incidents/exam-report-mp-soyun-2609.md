## 3. 두 번째 벽 — 도달했어도 막혔다 (catch-22)

설령 학생 워크스페이스에 들어갔더라도 다음 벽이 있다.

```ts
// student-workspace-client.tsx:366
const reportReady = student.gradingConfirmed || student.reportStatus !== "NONE";
const enabled = { read: true, verdict: verdictReady, analysis: verdictReady, report: reportReady };
```

- 「AI 리포트」 탭이 **`disabled`** → 눌러도 아무 반응·아무 안내 없음.
- 정작 안내와 [채점으로 이동] 버튼은 **`report-step.tsx:148` 안**에 있다:
  > "채점을 확정한 후에 리포트를 생성할 수 있습니다."
- **게이트의 설명이 게이트 뒤에 갇혀 있다.** 그게 필요한 사용자에게는 영원히 안 보인다.

답안 링크는 서버가 **전 문항 기입을 강제**(`INCOMPLETE` 400)하므로 "제출 완료 = 채점 완료"가 사실상
보장되는데도, `unknownCount=0` 상태에서 확정 넛지가 **0개**다.

## 4. 세 번째 벽 — 시험지가 4조각 (7월 장애의 잔재)

4개 분석의 문항은 **1~3 / 4~9 / 10~19 / 20~35**, 만점 합계 **6+17+30+47 = 100점**, 연속·무중복.
7페이지 35문항 한 장이 쪼개진 것이다. 7월 14~17일 **「3페이지 이상 업로드 전멸」 장애**
([[exam-report-mp-incident]])를 2페이지씩 쪼개 우회한 결과물이다.

### 근본 간극

- 고객의 모델: *"시험지를 올려서 아이에게 배포 → 아이가 풂 → 결과가 학생 시험 탭에 뜬다"*

이 간극을 **어느 화면도 설명하지 않는다.** ①②가 그 간극의 직접 증상이다.

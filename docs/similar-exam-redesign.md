# 동형 시험지 생성 — 재설계 설계서 (v1)

> 2026-06-05 원장님 합의. 기존 "시험지 전체 구조 패턴 → 자료풀 대량 재생성" 방식이
> 출제 의도 보존에 실패해 품질 이슈가 발생 → **문항 단위 내용 분석을 토대로** 재설계.

---

## 0. 배경 — 기존 방식의 한계

기존 동형 생성은 시험지 전체에서 **구조 패턴(슬롯: 문항번호·유형·배점·난이도)만**
추출해, 선생님이 고른 지문풀로 그 슬롯들을 대량 재생성했다. 즉 **구조만 베끼고
개별 문항의 "내용/출제 의도"는 분석하지 않았다.** 그 결과:

- 빈칸이 원문 구절을 그대로 복원하는 수준(추론 부재)
- 순서배열·문항 중복, 단일/짧은 지문에서 본문 환각
- 같은 자료로 만든 두 시험지가 사실상 동일

또한 생성 엔진(`runQuestionGeneration`)이 **문항당 AI 1회 독립 호출**이라:

1. **중복 문항** — 생성 중 다른 문항을 모름
2. **톤 불일치** — 호출이 독립적
3. **공유 지문 세트 내 정답 누출** — 다른 문항을 보고 정답 유추
4. **비용** — ~25콜/부 ≈ API ₩1000/부

---

## 1. 목표 & 범위

- **MVP**: 문항 1개 입력 → 분석 → 동형 문항 생성. 이후 **시험지 전체로 확장**.
- **분석 데이터 최대 추출**. **지문 없는 문항**도 지원(예: "다음 단어 쌍 중 관계가
  다른 하나는?" — 단어쌍 5개만 보기).
- **생성 방식(2-c)**: 참조 문제의 지문 재활용 ❌ / **별도 지문 입력 + 유형 적용** ⭕.
- **보류**: 강사 커스텀 유형(분석 MVP 후), 학생 성적/진단 분석(별도 기능).

---

## 2. 전체 파이프라인

```
[입력: 문항/시험지 — 사진·파일·텍스트]
  → ① 분석기            문항별 내용 분석 + (시험지면) 전체 분석 + 지문-문항 그룹핑
  → ② 생성 오케스트레이터  분석 스펙 + 별도 입력 지문 → 동형 문항 (세트 인지 배치)
  → ③ 공유 후처리·품질·누출게이트  (import 재사용)
  → ④ 저장 (기존 Exam + Question 재사용) → 미리보기
```

---

## 3. 엔진 분리 — "오케스트레이션만 자체, 품질은 공유"

전면 포크가 아니다. **생성 "호출(오케스트레이션)"만 동형이 자체 소유**하고,
품질·후처리·스키마·누출게이트는 공유 모듈을 **import 재사용**(드리프트 0).

| 구분 | 모듈 |
|---|---|
| 🆕 동형 자체 | 문항 분석기 / 생성 오케스트레이터(자체 프롬프트·세트인지 배치) / 유형 리졸버 |
| ♻ 공유 import | `question-quality`(검증) · `question-postprocess`(후처리) · `question-schemas`(출력 스키마) · `question-sets`의 `extractAnchors` + `scanSetForLeakage`(누출) |
| 🗎 존치(무영향) | 일반 문제 생성용 `runQuestionGeneration` — 동형은 더 이상 호출하지 않음 |

> 공유 엔진의 "유형/지문당 1콜" 강제가 동형 경로에서 사라지므로, 기존 유형-묶음
> 명령 충돌도 해소된다.

---

## 4. ① 분석기

입력 문항에서 **최대한 많이** 추출. 한 분석기로 단일 문항/시험지 모두 처리.

### (B) 문항별 내용 분석 — 핵심
- 발문 / 지문(**optional**) / 보기[] / **보기 개수** / 정답 / **중복정답 여부·정답 목록** / 원해설
- 유형 (빌트인 22 매칭 or "신규 후보") / **지문기반 vs 지문없음** / 객관식·서술형
- **출제 포인트** (무엇을 묻는가)
- **변형 분석** (무엇을 어떤 규칙으로 바꿔 출제했나 — 예: 수일치 `exhibit→exhibits`)
- **정답 논리** (정답 근거 + 오답별 왜 틀렸나)
- **난이도 + 근거**
- **재현 스펙** (발문/보기/정답 형식 — 동형 생성용)
- **변형 축** (출제 의도 보존하며 바꿀 수 있는 부분)

### (C) 지문-문항 그룹핑
- 입력이 "지문 + 여러 문항"이면 `{ 지문, 묶인 문항들 }` 단위로 추출. (예: [43~45], [18~19])

### (A) 전체 시험지 분석 — 유지
- 레이아웃·섹션·출제 구성 등 기존 "분석 정보"는 **그대로 유지**(시험지 생성에 필요).

> MVP는 (B) 중심. 시험지 입력 시 (A)(C)가 채워진다.

## 5. ② 생성 오케스트레이터

### 단일 문항 (MVP)
분석 스펙 + 강사가 넣은 별도 지문 → **동형 자체 프롬프트**로 1문항 생성
→ 공유 후처리·품질 통과 → 저장. (배치/누출/다이제스트는 아직 불필요)

### 시험지 확장 — 세트 인지 배치
- **순서대로 고정 크기 배치**(~3~5문항). 실제 시험지 순서가 유형 혼합이라 한 배치에
  다른 유형이 섞여 → 중복 위험↓.
- **공유 지문 세트는 한 배치에**(누출 방지의 유일한 하드 제약).
- **배치 크기 = 비용 ↔ 품질 다이얼**. (크면 싸고 주의 분산, 작으면 비싸고 정밀)
- 비용 절감 원리: 고정 스캐폴딩(출력형식·루브릭·계약)을 콜마다 재전송하지 않고
  배치당 1회로 분산 (25콜 → ~5콜).
- **배치 간 다이제스트**: 이미 생성된 문항의 요지·정답키·도입문구를 다음 배치
  컨텍스트로 주입 → 시험지 전체 차원 중복 억제 (추가 콜 0).
- **무지문 유형**: 자체 프롬프트에서 지문 생략 + 후처리 PASSTHROUGH/빈지문 경로 활용.

### 비용/품질 티어
- **스탠다드(기본)**: 배치 + 다이제스트 + **무료 결정적 누출게이트(`scanSetForLeakage`)**.
  → 현재보다 콜 ~5배↓ + 중복/톤/누출 해결.
- **프리미엄(옵션)**: + 전체 세트 **검수 1콜** + 탈락분 **타깃 재생성**(블랭킷 X,
  형제 문항 보고 재생성). 품질 백스톱. 비용 옵트인.

---

## 6. 재사용 / 신규 / 대체 / 보류

- ♻ **재사용**: 공유 품질·후처리·스키마·누출게이트, `Exam`+`Question` 저장, 전체 분석정보, UI 쉘.
- 🆕 **신규**: 문항 분석기(지문 optional), 동형 자체 생성 오케스트레이터, 무지문 경로.
- 🗑 **대체**: 동형이 `runQuestionGenerationWithEmptyRetry` 호출하던 부분 → 자체 오케스트레이터.
- ⏸ **보류**: 커스텀 유형, 학생 진단, 프리미엄 검수루프(스탠다드 후).

---

## 7. 구현 순서

1. **분석기** — 단일 문항, 풍부 스키마(지문 optional), 멀티모달 호출. ← 1순위
2. **단일 문항 동형 생성기** — 자체 프롬프트 + 공유 후처리/품질. 지문기반 먼저.
3. **무지문 경로**.
4. **시험지 확장** — 순서 배치 + 다이제스트 + 누출게이트.
5. (프리미엄) 검수 / 재생성.
6. (보류) 커스텀 유형.

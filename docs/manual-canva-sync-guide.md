## 1. 원칙 — 리포가 원본, Canva는 "다듬기·협업" 표현본

- **콘텐츠·구조의 정본은 리포 SVG.** 기능이 바뀌면 리포에서 먼저 고친다(아래 3장).
- **Canva는 시각 다듬기·타 유저 협업용 사본.** Canva에서 스타일을 손봤다면, 그 결과를
  다시 리포로 내보내 `public/manual`을 교체해야 앱에 반영된다(아래 4장, 역방향).
- 즉 **한쪽에서만 오래 작업하지 말 것.** 리포에서 콘텐츠를 크게 바꾸는 중이면 Canva 다듬기는
  잠시 멈추고, Canva에서 대대적으로 다듬는 중이면 리포 콘텐츠 변경을 미룬다. 둘을 동시에
  많이 벌리면 병합이 지옥이 된다.

## 2. 리포 → Canva 최신화 (지금 한 번에 맞추기)

Canva 문서가 13개(2026-07-11 가져오기)라 챕터 슬러그 12개+빠른가이드 구성이다. 이번에 ⑫가
새로 생겨 **14개**가 되어야 한다.

### 2-A. 기존 13개 문서: 페이지 통째 교체 (권장)

각 챕터 Canva 문서마다:
1. Canva에서 해당 문서 열기 → **모든 페이지 선택 후 삭제**(빈 문서로).
2. `업로드` → `~/Desktop/smoat-manual-canva-pdf-v2/<슬러그>.pdf` 가져오기 →
   PDF 페이지가 순서대로 삽입됨.
3. 저장. (편집 공유 링크 URL은 그대로 유지되므로 `canva-links.ts` 수정 불필요.)

> 페이지 교체가 번거로우면 **문서를 새로 만들어 PDF만 가져오고** 편집 공유 링크를 재발급해도
> 된다. 그 경우 새 링크를 `src/lib/manual/canva-links.ts`의 해당 슬러그에 갱신해야 어드민
> 「Canva 편집」 버튼이 올바른 문서로 연결된다.

### 2-B. ⑫ 학생 관리(BETA) — 신규 문서 만들기

1. Canva에서 **새 문서 생성** → `12-students.pdf`(5장) 가져오기.
2. **편집 가능 공유 링크 발급**(링크 소지자 편집 가능).
3. 그 링크를 `src/lib/manual/canva-links.ts`에 추가:
   ```ts
   "12-students": "https://canva.link/발급된링크",
   ```
   (현재 이 자리는 주석으로 비어 있음. 등록 전까지 어드민 「Canva 편집」 버튼은 ⑫에서만
   안전하게 미노출된다 — 컴포넌트가 링크 없음을 처리함.)

## 3. 앞으로 리포 콘텐츠가 바뀔 때마다 (반복 절차)

기능 개편·문구 수정 등으로 슬라이드를 고칠 때는 항상 이 순서:

1. **리포 SVG 제자리 후처리** — `public/manual/redesign-185/<슬러그>/NNN.svg` 직접 수정.
   ⚠️ `npm run build:slides`로 재생성하지 말 것(수작업 검수분이 날아감 — rebuild 금지 원칙).
2. **슬라이드 삽입/삭제가 있었다면** 전 슬라이드 재번호(N/총장수)·챕터 진행바·전체 목차
   (`00-intro/002.svg`)·`slides.json`·`review.html`·작업본 `index.html`까지 함께 갱신.
   (단순 문구 수정만이면 이 단계 불필요.)
3. **2사본 동기** — 작업은 `public/manual`에서 하고 `manual-slides/redesign-185`로 rsync,
   `diff -rq` 로 **diff 0** 확인. (두 사본: 앱이 읽는 프로덕션본 = `public/manual`,
   작업본 = `manual-slides`.)
4. **검증** — 변경 SVG를 `xmllint --noout`로 XML 검사 + PNG 렌더로 육안 확인
   (넘침·겹침·핑 위치). 넓게 바꿨으면 아래 5장의 감사 스캔을 다시 돌린다.
5. **Canva PDF 갱신** — `npm run build:canva-pdf <슬러그>` (또는 `all`) →
   `~/Desktop/smoat-manual-canva-pdf-v2/<슬러그>.pdf` 재생성.
6. **Canva 반영** — 2-A 절차로 해당 챕터 문서 페이지 교체.
7. **앱 반영** — `public/manual`이 이미 최신이므로 배포(커밋·푸시)하면 앱은 바로 반영.

## 4. Canva에서 다듬은 것을 리포로 되가져오기 (역방향)

Canva에서 스타일/레이아웃을 손봤다면:
1. Canva에서 **PDF 또는 PNG로 내보내기**(챕터별).
2. PNG면 슬라이드별로 `public/manual/redesign-185/<슬러그>/NNN.svg`의 임베드 스크린샷/전체를
   교체, PDF면 페이지→슬라이드 매핑 후 반영. (SVG 구조를 유지하려면 텍스트/도형은 SVG로,
   스크린샷만 이미지로 두는 현재 구조를 지킬 것.)
3. 2사본 동기 + 검증 + 배포.

> 완전히 Canva를 원본으로 전환하려면(원래 `claude-design-canva-integration.md`의 방향),
> SVG 파이프라인을 은퇴시키고 "Canva 수정 → 일괄 내보내기 → public/manual 교체"만 남긴다.
> 다만 지금은 기능 변경이 잦아 **리포 SVG를 원본으로 유지**하는 편이 현실적이다(제품이 자주
> 바뀌면 스크린샷·문구를 코드 옆에서 갱신하는 게 빠르다).

## 5. 품질 감사 재실행 (넓게 고친 뒤 권장)

슬라이드를 많이 손댔으면 배포 전 감사로 잘림·겹침·핑 오위치를 잡는다. 이번(2026-07-23)에
쓴 방법이 스크래치패드에 남아 있고, 핵심은 리포에서 재현 가능하다:

- **구조 스캔(결정적)** — 핑 하이라이트 박스가 스크린샷 이미지 영역을 벗어나는지, 텍스트가
  하단 진행바(y=1028)를 침범하는지, z-order상 이미지 뒤에 텍스트가 깔렸는지. (전부 좌표 사실이라
  오탐 없음.)
- **헤드라인 폭 스캔** — 우측 패널 fs35~38 헤드라인 한 줄의 "한글등가 길이"가 ~17을 넘으면
  슬라이드 오른쪽에서 잘림 위험(특히 `—` em-dash 포함 줄). 한 줄 ≤ 약 15자로 재줄바꿈.
- **불릿 겹침/근접 스캔** — 우측 패널 fs19 불릿 tspan y가 서로 ≤4px면 겹침, fs19 마지막 줄과
  하단 노트(fs17)가 <22px면 밀착 → 불릿 축약 또는 재배치.
- **육안 검수** — 196장을 1920×1080 PNG로 렌더해 배치로 나눠 눈으로 확인(잘림·어색한 줄바꿈·
  숨은 텍스트·핑 오위치 4종). 프로그램이 못 잡는 핑 대상 오인·숨은 텍스트는 이걸로만 잡힌다.

**주의 — 오탐 아님으로 확정된 것들**(감사 시 결함으로 세지 말 것):
- **`◈N` 크레딧 표기** — 매뉴얼의 의도된 관례. 003(보는 방법) 슬라이드가 "크레딧 칩(◈)"으로
  정의하고 8챕터 30여 파일에서 일관되게 쓴다. (앱 UI의 CreditCostChip 규칙과는 별개 매체.)
- **핑 뱃지가 대상 라벨 앞 글자를 살짝 덮음** — 덱 전반의 "대상 좌상단 앵커" 표준 배치.
- **스크린샷 내부 UI 글자가 카드 경계에서 잘림** — 원본 제품 스크린샷이라 무관.

## 6. MCP 자동화 (선택 — 재인증하면 내가 대신 함)

Canva MCP를 인터랙티브 세션에서 재인증(`/mcp` 또는 `claude mcp` + OAuth)하면, 위 2·3·4장의
Canva 가져오기/페이지 교체/내보내기를 Claude가 대신 수행할 수 있다. 현재는 토큰 만료 상태라
불가(비대화형 세션에선 OAuth 진행 불가). 재인증 후 "캔바에 최신 PDF 반영해줘"라고 지시하면 됨.

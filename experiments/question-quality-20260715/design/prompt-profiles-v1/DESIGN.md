# Prompt/structure profile design v1

## Verdict

Four arms per focus type are specified, but none is promoted and no call is authorized. The design rejects a binary “more versus fewer constraints” story. It separately estimates:

1. a single repeated-block deletion;
2. a compact positive construction procedure using the current schema;
3. a compact structured planning artifact that changes the schema;
4. the source-pinned current control.

The structured grammar arm certifies one safe CORE-10 site before mutating only that site in the same provider call. The structured blank arm declares the answer meaning axis and five option intents before rendering options in the same provider call. “Same call count” does not mean “same tokens” or “free”; token and USD deltas are explicit outcomes.

## Why these are different causal treatments

`G1` asks whether the final repeated checklist itself helps or overloads the general grammar path. `G2` changes representation from dispersed prohibitions/candidate prose to a short positive procedure while leaving the output schema alone. `G3` changes both representation and schema order, forcing an auditable site certificate before the full question. A `G3 > G2` result would support the structured artifact, not merely shortening.

`B1` removes unrelated type sections only from STANDARD. It is byte-identical to `B0` on PREMIUM, so no duplicate PREMIUM `B1` provider rows are scheduled; the static surface table retains that row only to prove the no-op. Because it has no distinct two-plan treatment, `B1` is also ineligible for the frozen two-plan `S2`; a safe `B1` screen result is descriptive and yields blank `S2=NO_ARM`. `B2` replaces the long instruction surface with a positive procedure but retains the free-text planning field. `B3` forces a typed answer axis, slot contract, and option-intent ledger. A `B3 > B2` result would support explicit option architecture, while `B2 > B0` with no `B3` gain would argue against extra schema burden.

This separation also exposes model interactions. Flash may benefit from a smaller search space, ignore schema planning, or lose useful redundancy. Pro may exploit the structured artifacts better, or spend extra output tokens without craft gains. No direction is assumed.

## Grammar site certificate

### One-call mechanism

The question schema replaces the server-stripped `errorDesign:string` with `siteCertificate:object`, placed immediately after `direction` and before `markedExpressions`. The model must first provide:

- exact source sentence, expression, and dependency window;
- one CORE-10 code (`a`–`i`, `k`);
- the governing structural rule;
- source form, sole displayed mutation, and correction;
- the strongest alternative parse and why it fails;
- an assertion that only the certified site is mutated.

The remaining question fields are then generated in the same response. A research adapter serializes the certificate back into `errorDesign` and passes the otherwise current question object through the current post-process and validators. This is call-count-neutral versus a one-shot control, but it is not token-neutral and it is not the deployed schema.

For eligible PREMIUM grammar confirmation, the analogous draft replaces `answerDesign` only in the existing answer-only stage. The control is the actual eligible production ladder: answer-only, add-decoys, current finalize/validators, hard regeneration or targeted repair when triggered, the current grammar solver, and the legacy fallback/salvage behavior when triggered. The treatment preserves that topology and changes only the answer-stage planning field to `siteCertificate`; the add-decoys prompt/schema and all downstream policies remain locked. A one-shot Pro general-path row is only an `S1` mechanism control and is forbidden as the `S2` production-topology control.

### Acceptance checks independent of the model's claims

A certificate is accepted only when deterministic binding confirms all of the following:

- exact source expression/window membership and single intended occurrence;
- CORE-10 code and surface-token compatibility;
- source form equals correction;
- exactly one `isError=true` marker and complete field equality to the certificate;
- every non-answer marker remains source-exact;
- minimal-span and visible-surface reconstruction pass;
- all existing grammar validity/explanation gates pass.

The model's sentence “whyAlternativeFails” is evidence for adjudication, not proof. The separate validation hypothesis compares the current key-convergence solver with an expanded blind solver response containing `correctedForm`, `isKeySurfaceUngrammatical`, `governingRule`, and per-option validity. That solver experiment is an additional measured call and cannot be smuggled into the one-call cost claim.

### Beautiful KILLER grammar

A KILLER grammar item can receive the beauty designation only after every validity invariant passes. The answer must require the intended nonlocal structural dependency, all four non-key markers must be genuinely competitive structural decisions, the sole mutation must be minimal and natural rather than a nonce-word or visual giveaway, and a concise accurate explanation must make the resolution inevitable. Each decoy is judged separately before its four-decoy counts are derived; a polished certificate cannot compensate for a weak student-visible choice.

### Grammar hypotheses

- `H-G1`: removing only the final checklist has a non-monotone effect; it may reduce instruction collision without changing fatal validity.
- `H-G2`: positive CORE-10 procedure improves structural-decoy rate and reduces fabricated point codes relative to current control at equal candidate-call count.
- `H-G3`: typed site certification reduces no-answer/multiple-answer and explanation-rule errors relative to positive free text.
- `H-G4`: `G3-G2` is larger on Pro than Flash, but the interaction direction is not assumed.
- `H-GV`: expanded solver evidence improves fatal-defect recall per added USD versus key-only convergence, with false-block rate bounded on clean historical items.

## Blank answer axis and option-intent ledger

### One-call mechanism

The question schema replaces the server-stripped `blankDesign:string` with `blankBlueprint:object`, before target and option fields. It contains:

- exact target expression/window and discourse role;
- answer meaning axis preserving proposition, relation, scope, stance, and polarity;
- one to three exact evidence anchors;
- a shared slot contract: exact prefix/suffix, syntactic category, polarity, scope, and register;
- exactly one correct intent and four distractor intents;
- for every distractor: borrowed passage concept, one primary error mechanism, semantic overlap/error distance, decisive exclusion evidence, mutual exclusivity with the answer, and same-slot proof;
- a preliminary seam audit.

`proposedText` is written in the ledger before `options` and must be copied byte-for-byte into the corresponding option. The research adapter serializes the blueprint into `blankDesign`, strips the experimental field from the student object, and applies existing post-process, reconstructed `prefix + option + suffix` seam checks, validators, and blind adjudication.

The ledger is not accepted as self-verification. The server recomputes option equality, seam, evidence membership, polarity/length/register features, intent uniqueness, and answer-option binding. A model that marks all seam booleans true but produces a broken option fails.

### What “beautiful KILLER” means here

A KILLER blank receives the beauty designation only if validity is already perfect and both blind evaluators agree on all four properties:

1. the answer requires synthesis of the right evidence rather than local synonym matching;
2. every wrong option is tempting for a recognizable passage-grounded reason;
3. every wrong option has one decisive, teachable flaw and no second cheap giveaway;
4. after reading the explanation, the answer feels inevitable without making the distractors look silly.

The packet records each option's intended role, but evaluators initially see only the student surface. Intent realization is scored only after they independently solve and explain elimination. This prevents a polished ledger from receiving credit for a weak visible item.

### Blank hypotheses

- `H-B1`: removing unrelated STANDARD contract sections changes quality, but the sign is unknown.
- `H-B2`: positive procedure improves seam validity and near-miss diversity relative to free-form current control.
- `H-B3`: typed intent ledger improves intent realization, unique-answer clarity, and beautiful-KILLER rate beyond the positive prompt alone.
- `H-B4`: the ledger's gain may be larger on Pro, while its token penalty may erase cost-per-ship-ready gains.
- `H-B5`: seam errors are best blocked deterministically; ledger fields should improve generation but never replace server recomposition.

## Matched design and sample accounting

This design has two different estimands and does not pretend their units are interchangeable. `S1` is a deliberately bounded, one-candidate-request mechanism screen. `S2` is a production-topology confirmation in which a randomized assignment can consume many physical calls and more than one candidate-capable response. The broader symbolic reduced registry's `342` slots per focus type cannot be used to authorize `S2`.

### Development screen

Grammar: `4 profiles × 2 plans × 2 difficulties × 6 passage clusters = 96` fixed single-shot calls. Blank: STANDARD contributes `4 × 2 × 6 = 48`; PREMIUM contributes only the three distinct surfaces `B0/B2/B3`, or `3 × 2 × 6 = 36`; blank total is `84`. Total `S1` consumption is therefore `180` candidate-capable calls, not `192`. Only INTERMEDIATE and KILLER are screened. Every admitted passage is crossed with every applicable frozen cell, so contrasts are paired within passage. The six passages are development-only.

The screen is for gross safety and deterministic arm eligibility, not an efficacy estimate. With only six clusters, raw A/B, beauty, and cost point estimates cannot rank arms. Challengers are checked in the precommitted priority order `G3, G2, G1` and `B3, B2, B1`; the first arm passing every safety/binding/cost criterion advances. If none passes, or the control itself fails, the result is `NO_ARM`. There is no effect-size tie-break, p-value tie-break, top-up, or early efficacy win.

### Frozen holdout

Per type the target is `2 profiles × 2 plans × 3 difficulties × 20 passage clusters = 240` randomized ITT assignments. This is explicitly **not** a claim of 240 candidate slots. The two profiles are the source-pinned control and one selected non-control. The 20 passages are disjoint from development and unseen by profile authors before freeze. Each plan/difficulty cell has 20 paired passage observations; inference is clustered by passage.

`S2` may open only after a fresh, independently reviewed callgraph proves the entire fixed 240-assignment queue for a type fits the remaining global candidate/physical/USD ceilings. Partial sequential admission is not a confirmatory substitute. The stale historical callgraph numbers are retained only as pessimistic blockers, never as execution permission, and the topology envelope status is explicitly `SOURCE_UNPINNED_BLOCK`. Consequently this v1 artifact does not add `480` holdout assignments to `180` screen calls and call the result `660 candidates`; no production-topology candidate total has yet been proved.

Twenty holdout clusters can detect only material effects with useful confidence. It cannot establish tiny differences. The absolute fatal-free noninferiority margin is frozen at `-5` percentage points. If the one-sided cluster-aware 95% lower bound does not exceed `-0.05`, the result is inconclusive or harmful, not noninferior. No post-hoc top-up is allowed.

## Difficulty-specific estimands

| Type | BASIC | INTERMEDIATE | KILLER |
|---|---|---|---|
| Grammar validity | locally provable unique error | nonlocal structure, unique error | layered/nonlocal structure, still indisputable |
| Grammar craft | clear educational decoys | four genuine structural decisions | all decoys competitive; answer not a scan shortcut |
| Blank evidence | direct restatement | two linked nearby clues | thesis convergence and multi-clue synthesis |
| Blank distractors | plausible, not random | one-axis near misses | high semantic overlap, one subtle fatal flaw each |

The locked six-test family uses the preregistered within-passage cluster outcome: for each profile and passage, average all six sealed plan-by-difficulty ITT cells, then form the paired challenger-minus-control difference. Plan-, difficulty-, and interaction-specific estimates are mandatory secondary diagnostics and release guards; they cannot replace a failed primary test or rescue a plan/difficulty regression. All raw cell counts remain visible, so the pooled primary cannot be reported without disclosing any Flash, Pro, BASIC, INTERMEDIATE, or KILLER harm.

## Outcome hierarchy

1. **Validity invariants:** source binding, grammatical surface, unique answer, correct explanation, scoring/display synchronization. Any failure is fatal.
2. **Exam readiness:** natural English/Korean, calibrated difficulty, evidence-grounded distractors, concise complete explanation.
3. **Craft:** distractor intent realization, decision time, structural depth, absence of style/polarity shortcuts.
4. **Beauty:** the KILLER criteria above. Beauty is undefined for invalid items, not scored as zero-quality prose.
5. **Economics:** input/output tokens, every physical call, latency, raw USD/candidate, USD/fatal-free, and USD/A-or-B item.

Prompt characters and directive counts are mediators/diagnostics, never primary outcomes.

## Blinding and adjudication

Packets remove plan, model, profile, prompt length, cost, retry count, gate status, intent ledger, certificate, and stored answer. Each evaluator first solves the visible item and may answer `NO_ANSWER` or `MULTIPLE`. Only then do they inspect the proposed key/explanation and complete option-level craft judgments. Two independent judgments are preserved; a third fresh adjudicator resolves disagreements.

Generator model self-grading is not the primary evaluator. Deterministic validators may triage, but all intention-to-treat rows—including parse failures, `NO_SAFE_SITE`, gate rejects, timeouts, provider failures, budget-admission violations, and unresolved adjudication—remain in denominators. `rubric-v1.json` freezes the exact validity/readiness/craft/beauty fields, A/B/C/F derivation, and cost handling. Every non-parsed/unresolved randomized row is `fatalFree=0`, grade `F`, and `AorB=0`; missing/disputed billing for a started call fails the economic gate instead of being dropped or imputed. A post-randomization `BUDGET_NOT_ADMITTED` or orchestration error invalidates confirmatory success.

## Selection, stopping, and holdout lock

Before calls, freeze source hashes, prompt/schema hashes, passage IDs/content hashes, row order, model IDs, thinking-off request, output caps, price snapshot, assignment envelopes, and evaluators' rubric.

During development, stop an arm only for the preregistered safety conditions in `profile-spec.json`. At the end of the full six-cluster block, select at most one arm per type using the fixed priority order, but only among arms that clear all parse, binding, deterministic-validity, discordance, and numeric per-call cost gates. The screen's raw craft point estimates are descriptive and never rank or break a tie. If no arm clears, or the control fails, select `NO_ARM`.

The confirmatory primary family is exactly `G_FATAL_NI, B_FATAL_NI, G_AB_SUP, B_AB_SUP, G_COST_NI, B_COST_NI`, in that order. Holm step-down controls familywise alpha at `0.05`. Grammar advances only if `G_FATAL_NI/G_AB_SUP/G_COST_NI` all reject after six-test adjustment; blank analogously requires all three `B_*` gates. An unrun/`NO_ARM` type contributes p-values of `1`, preserving the frozen family. Raw p-values use the paired 100,000-replicate cluster bootstrap frozen in `rubric-v1.json` and `profile-spec.json`; their test IDs, type-gate arrays, and p-value algorithm are verifier-checked for byte equality. Failure, harm, and inconclusive results all preserve the current default. No winner is promoted directly from this experiment; route-parity confirmation, deployment provenance, regression tests, and a reversible feature flag are still required.

## Cost model

The pinned price snapshot is stale for execution and is used only for planning. Conservative rates below 200k prompt tokens are:

| Model | Input USD/token | Output USD/token |
|---|---:|---:|
| Gemini 3.5 Flash | 0.0000027 | 0.0000162 |
| Gemini 3.1 Pro preview | 0.0000036 | 0.0000216 |

For Pro, any-tier conservative rates are higher and the sealed controller must reserve against the applicable worst tier. Expected scenarios use the measured 2.2696 chars/token calibration and show 1.8–3.0 sensitivity. Planning completions are 4,000 tokens for grammar and 2,500 for blank, while the sealed `S1` hard output caps are 6,000 and 4,000 respectively. Numeric `S1` per-call USD ceilings are `$0.20` grammar STANDARD, `$0.43` grammar PREMIUM, `$0.14` blank STANDARD, and `$0.20` blank PREMIUM. A fresh request-price preflight exceeding one blocks the unopened registry rather than silently resizing it. Premium grammar ladder confirmation must separately reserve every answer, decoy, retry, repair, solver, fallback, and salvage call under a fresh whole-assignment envelope.

Cost-neutral in this design means **no extra logical candidate-generation stage** for `G3` STANDARD or `B3`; it never means zero token or dollar delta.

## Go/no-go boundary

This artifact remains `DESIGN_ONLY_NO_GO`. Before any row can run, the parent campaign still needs:

- fresh PASS on provider/controller/parser binding and bypass audit;
- complete call-site scopes and candidate finalization;
- current callgraph envelopes;
- sealed source-bound passage queue;
- a price snapshot fresh enough for the controller policy and provider-side spend cap;
- zero-network exact-wire tests for every profile, plan, and stage through the real provider transform, response-byte adapter binding, and current postprocess/validator replay;
- independent review of this design and schema compatibility;
- explicit merge into the global ≤1,000 registry.

No production default, retry policy, ladder, prompt, schema, or feature flag was changed here.

The 23 nonfocus types × 12 symbolic rows are coverage smoke and defect discovery only. A found defect is an existence proof; a clean set cannot support a type-level improvement, noninferiority, model-comparison, or release claim.

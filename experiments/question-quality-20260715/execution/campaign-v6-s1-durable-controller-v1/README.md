# Campaign v6 S1 per-assignment durable controller

This package is the zero-network materializer for the future rights-clear v6 S1 campaign. It fixes the graph-cap defect that would occur if all 180 exact requests were placed in one controller registry: each assignment gets its own sealed registry with one root candidate entry, one use, one candidate opportunity, one physical fetch, and a conservative price envelope. All 180 registries must debit one shared durable `BudgetStore` batch capped at 180 candidate opportunities, 180 physical fetches, and the sum of the 180 emergency price reservations. Candidate capacity is never recycled and queue top-up is forbidden.

The v1.2 materializer also seals the complete confirmatory matrix instead of trusting TypeScript declarations or a total row count. Six grammar passages each contain all `G0/G1/G2/G3 x Standard/Premium x Intermediate/Killer` cells (96). Six blank passages each contain `B0/B2/B3 x Standard/Premium x Intermediate/Killer` plus Standard-only `B1 x Intermediate/Killer` cells (84). The aggregate is exactly Standard 96, Premium 84, Intermediate 90, Killer 90. Grammar output is capped at 6,000 tokens and blank output at 4,000 tokens. Unknown enum values, a missing or duplicated cell, cross-type passage reuse, fewer than twelve distinct passage/rights hashes, B1 Premium, and profile-ID/hash collisions all fail closed. Caller-owned profile/pricing objects are canonical-cloned and the complete campaign is recursively frozen, including children of an already shallow-frozen parent.

The persisted artifact is intentionally a synthetic fixture. It contains no passage text, makes no provider request, mutates no production database, consumes zero API candidates, and cannot produce a live execution permit. The real v6 original-corpus exact-wire preflight can later be mapped into the same `S1MaterializationInput` only after rights, PII, privacy, pricing, credential, and independent-audit holds close.

## Fail-closed contracts

- Standard uses `google/gemini-3.5-flash`; Premium uses `google/gemini-3.1-pro-preview`.
- Every request is the exact OpenRouter chat endpoint, one completion, one schema-bounded question, reasoning off, and provider routing `{only/order:["google-vertex/global"], allow_fallbacks:false, require_parameters:true, data_collection:"deny", zdr:true}`.
- Pricing schema v2 requires an explicit, unique endpoint `tag`, an exact provider, and a snapshot-authorized requested/canonical served-model allowlist. Every active endpoint must have finite positive base rates; an omitted override dimension explicitly inherits its base rate, while null/string/non-finite rates fail. Text input/output charges are modeled and cache/reasoning/image/web/fixed-fee dimensions must be explicitly inapplicable; unknown dimensions reject. Admission is bound to the exact `google-vertex/global` rate/provider and the local reservation uses the maximum across every active endpoint/service tier.
- The externally preregistered snapshot hash is separate from the snapshot object's self-hash. Tag omission, duplicate tags, and post-registration tag swaps fail closed.
- The research boundary injects `X-OpenRouter-Metadata: enabled` only inside an active research scope; the ordinary production fast path still forwards the exact original input/init/promise. Successful schema-v2 responses retain the raw body privately and are quarantined unless metadata proves one direct, non-BYOK, successful selected-provider attempt. OpenRouter metadata currently identifies the selected provider/model but does not promise the service-tier tag, so the exact tier remains enforced by the request `only` contract and tagged price proof.
- Live helpers require an operator-signed authorization capability bound to the introspected credential public ID. Authorization windows form one append-only predecessor chain with a stable credential ID and monotonic provider usage; each window reconciles durable local actual/effective cost after bounded provider polling. A generic `OPENROUTER_API_KEY` is never accepted as fallback. The child environment copies only minimal OS/runtime variables; HOME, USERPROFILE and application-data paths are excluded. Production `runtime.ts` exports no test trust root, credential, permit, reserve, runtime, or finalize seam. Offline tests live in a module excluded from the production import closure; its distinct permit brand accepts only module-created OS-temp stores, retains no secret, emits no credential environment/header, and constructs a bookkeeping controller with no transport delegate.
- A permit is usable only inside the overlap of its credential-metadata and rolling schema-v2 tagged-price windows (at most 15 minutes). The 180-row campaign, registries, frozen emergency price envelope, and `durableBatchIdentitySha256` never change between windows. That identity includes a timestamp-free `frozenPricingEnvelopeSha256` over per-model emergency ceilings, safety multiplier, server overhead, and global reserved cost: a mere snapshot-time refresh preserves identity, while a changed initial ceiling cannot collide. `reserveS1CampaignBatch` uses that stable identity, so refresh is idempotent against the same SQLite batch rather than creating or splitting a new batch. The next runtime requires a newly sealed permit; any current all-active rate above the frozen envelope fails before a lease.
- `reserveS1CampaignBatch`, assignment admission, and the instant before every physical lease recheck the permit, durable authorization head, provider usage/remaining, and rolling pricing window. The runtime constructs the frozen parser internally; callers cannot inject a same-hash parser implementation. Expired/stale permits stop new work. Candidate capacity remains permanently consumed and no queue top-up is possible.
- The response parser requires exactly one OpenRouter choice. Two valid choices, a valid plus malformed extra choice, or any other choice-cardinality drift consumes the reserved maximum and quarantines the assignment. A single choice containing two full-question objects exposes both objects to the durable overflow gate, which also quarantines without replay or capacity recycling.
- Every registry provenance record and public assignment retains both the exact request-envelope hash and prompt-profile artifact hash; a materialized row cannot silently lose the artifacts needed to reconstruct or audit the experimental cell.
- Restart and duplicate safety remains in the append-only durable controller/ledger: call leases are committed before network I/O, the same call/ordinal cannot replay, parser/route/generation-ID failures become durable unknown/quarantine evidence, `never-sent` cannot contradict an existing clone/body, and final usage cannot be overwritten. A zero-dispatch assignment cannot close. The sealed batch can terminate only as `COMPLETE` (all 180 exact members closed with one consumed dispatch each) or explicit `ABORTED_INCOMPLETE`.
- Existing schema-v4 ledgers are resumed through one checked additive migration: if the nullable `rolling_pricing_attestation_hash` call-contract column is absent, it is added before any new lease, then its SQLite type/nullability/key shape is verified. A malformed look-alike column fails closed. The migration test removes the column from a real v4 fixture, reopens it, and proves a rolling-attestation hash can be durably written and recovered.

## Live authorization remains blocked

The public key currently pinned in `runtime.ts` is an explicitly labeled non-signable placeholder; its private half was discarded. Before any live run, a separately reviewed and sealed amendment must pin the real operator public key and document an offline signer process. The private key must be generated/held outside the repository and child environment, never logged or persisted in artifacts, used to sign each fresh bounded window, and zeroized under an auditable custody procedure. The live launcher must also run from a fresh isolated working directory and prove its transitive import closure contains no `loadEnvConfig`, dotenv, or repository `.env*` reader; a sentinel `.env` test is required. Until that amendment and test exist, no production permit can be signed and no live dispatch is authorized.

This S1 controller is only a single-shot experimental screen (one frozen assignment, one dispatch). It does not claim parity with the production Premium grammar ladder, retry, repair, or regeneration topology; that topology requires a separate current-code audit.

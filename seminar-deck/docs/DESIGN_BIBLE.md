# SMOAT LINE — DESIGN BIBLE

> 팬아웃 에이전트 **필독 1순위**. 여기 없는 수치·색·폰트를 새로 만들면 critical 위반이다.

---

## 1. 캔버스 & 안전영역

- 캔버스 **1920 × 1080 절대 px**. `%`·`vw`·`vh` 사용 금지(예외: 슬라이드 내부 그리드의 `1fr`, `flex:1`).
- 스테이지는 엔진이 `transform: scale()`로 맞춘다. 슬라이드는 항상 1920×1080이라 가정하고 짠다.
- **안전영역**: 상 `96px`(HUD 점유) / 하 `100px`(READOUT 56px + 여유) / 좌우 `96px`.
  → 콘텐츠 박스는 `.pad` 유틸(`position:absolute; inset:96px 96px 100px;`)을 쓰면 자동 적용.
- 안전영역 밖으로 나가도 되는 것: 의도적 블리드 배경(이미지·그라데이션), 데코 도형. **텍스트는 절대 불가.**
- `.src-line`(출처/각주)은 `right: 96px; bottom: 22px` 고정 — READOUT과 겹치지 않게 이미 계산돼 있다. 위치를 바꾸지 마라.

## 2. 슬라이드 파일 규약 (위반 시 build.mjs 실패)

```html
<section class="slide slide--dark" id="sNN"
  data-title="ST 02"          <!-- HUD 표기용 짧은 라틴 코드네임 -->
  data-kr="문항 25유형"        <!-- 한글 제목 (레일 툴팁 · LINE MAP) -->
  data-zone="생성"             <!-- 구역: 개막/문제/생성/산출/전환/학습/회수/확장/정리 -->
  data-zone-en="GENERATE"
  data-part="PART 1 — 기능 브리핑"
  data-in="분석된 지문"        <!-- 하단 READOUT 좌측 -->
  data-out="객관식+서술형 문항" <!-- 하단 READOUT 우측 · LINE MAP 셀 설명에도 쓰임 -->
  data-note="크레딧 차감 없음"  <!-- 선택: READOUT 우측 노트. 없으면 속성 생략 -->
>
  <div class="pad"> … </div>
  <style>#sNN { … } /* 반드시 #sNN 스코프 안에서만 */</style>
  <script>(() => { /* IIFE. 전역 오염 금지 */ })();</script>
</section>
```

- 파일 1개 = `<section>` 1개. `id`는 파일명과 동일(`s07.html` → `id="s07"`).
- **모든 CSS 셀렉터는 `#sNN` 으로 시작**한다. 전역 셀렉터(`.card{}`, `body{}`) 재정의 금지.
- `<style>`·`<script>`는 section **안**에 둔다.
- 스크립트는 IIFE. 전역 변수·전역 이벤트 리스너 금지(필요하면 `document.getElementById('sNN')` 하위에만 바인딩).

## 3. 스텝(리빌) 규율

- `data-step="0"`은 슬라이드 진입 시 즉시 노출. `1,2,3…`은 → 키로 순차 노출.
- **슬라이드당 스텝 최대 5** (0 포함 6단계). 세미나 10분 브리핑이므로 스텝이 많으면 진행이 막힌다.
- `data-fx="left|right|scale|none"` 로 등장 방향 변경 가능. 기본은 아래에서 위로.
- 캡처는 `#/N/9`로 최종 스텝 상태를 찍는다 → **최종 스텝에서 레이아웃이 완성**돼야 한다. 스텝이 겹쳐 깨지면 안 됨.
- 자동 재생 애니메이션(무한 루프)은 허용하되, 캡처 시점에 화면이 비어 보이면 안 된다.

## 4. 색 (tokens.css 변수만 사용 — 하드코딩 hex 금지, 단 슬라이드 내부 제품 UI 재현은 예외)

| 용도 | 변수 |
|---|---|
| dark 배경 | `--ink` `--ink-2`(카드) `--ink-3`(보더) `--ink-4` |
| paper 배경 | `--paper` `--paper-2` `--paper-3` |
| 주인공 | `--blue` `#3B82F6` / `--blue-deep` / `--blue-light` / `--blue-sub` |
| 정답·완료·가동 | `--emerald` |
| 취약·주의·진행중 | `--amber` |
| 오답·결손 | `--red` |
| 보조 데이터 | `--indigo` `--purple` |
| dark 위 텍스트 위계 | `--txt-1` `#E8EDF7` / `--txt-2` `#97A3B8` / `--txt-3` `#7E8AA0` / `--txt-4` `#6E7A90` |
| 텍스트 보조 | dark 위 `--grey`(모노 라벨), paper 위 `--grey-d`/`--g500` |
| 회색 스케일 | `--g50` … `--g900` (제품 UI 재현용) |

**dark 표면 회색 규율 (2026-07-24 개정)** — 이전 판은 "토큰 밖 색 금지"만 적었고 dark 위 텍스트
위계를 위한 회색 스케일을 제공하지 않아, 슬라이드마다 `#93A0B5` `#7E8AA0` `#6E7A90` 같은
값을 개별 정의하는 결과를 낳았다(견본 포함). 그 값들은 실제로 하나의 슬레이트 계열을 이루고
있었으므로, **관행을 정본으로 승격**해 `--txt-1~4` 로 등재한다.
- 신규 작성 시에는 **반드시 `--txt-1~4` 를 쓴다.**
- 기존 슬라이드의 근사값(±8 이내 슬레이트 계열)은 같은 위계로 간주하며 결함이 아니다.
- 이 4단 밖의 새 회색을 만드는 것은 여전히 금지다.

**의미 규율(전 장표 공통 — 어기면 청중이 혼란한다)**
- 파랑 = SMOAT / 시스템 / 선생님 행동
- 초록 = 정답 · 완료 · 성장
- 주황 = 취약 · 보강 필요
- 빨강 = 오답 · 결손
- 회색 = 미착수 · 비활성

**금지**: 보라 그라데이션, 무지개 팔레트, 네온 남발, 토큰 밖 새 색 정의.

## 5. 타이포

| 클래스 | 스펙 | 용도 |
|---|---|---|
| `.h1` | Paperlogy 800 / 92px / lh 1.06 / ls -.026em | 장표 대표 헤드라인 |
| `.h2` | Paperlogy 800 / 68px / lh 1.10 | 섹션 헤드라인 |
| `.h3` | Paperlogy 700 / 42px / lh 1.20 | 블록 제목 |
| `.h4` | Paperlogy 700 / 28px / lh 1.30 | 카드 제목 |
| `.lead` | Pretendard 400 / 22px / lh 1.62 / `--grey` | 부제·설명 |
| `.body` | Pretendard 400 / 17px / lh 1.70 | 본문 |
| `.kicker` | IBM Plex Mono 600 / 12.5px / ls .22em / `--blue` | 장표 상단 라벨 |
| `.mono` | IBM Plex Mono | 계기·수치·라벨 |
| `.latin` | Archivo + uppercase | **라틴 전용**. 한글에 절대 적용 금지 |

- 대형 타이포는 `letter-spacing`을 음수로 조인다(-.02 ~ -.035em). Paperlogy는 자간이 넓다.
- 한 장표에 **폰트 크기 4단계 이내**. 5단계 이상 쓰면 위계가 무너진다.
- 줄바꿈은 `<br>`로 **의미 단위**에서 직접 끊는다. 자동 줄바꿈에 맡기지 마라.
- `word-break: keep-all` 전역 적용됨 — 어절이 안 쪼개진다. 대신 긴 어절은 컨테이너 폭을 키워라.
- Paperlogy 특수문자(`→ × № ⓒ`)는 **글리프 구멍 위험** → 화살표·기호는 `.mono` 스팬으로 감싸라. 안전 문자: `· ▸ ↺ ✓ ─`

## 6. 여백 리듬 (8px 그리드)

- 기본 단위 8. 허용 간격: 8 / 12 / 16 / 24 / 32 / 44 / 56 / 72 / 96 / 128
- 헤드라인 ↔ 리드: `24~32`
- 리드 ↔ 본문 블록: `44~56`
- 카드 간 gap: `16~24`
- 섹션 블록 간: `72~96`
- **좌우 여백 비대칭 금지.** 콘텐츠는 `.pad` 안에서 좌우 균형을 유지한다(의도적 좌측 정렬 레이아웃 제외).

## 8. 인터랙션 규율

- 클릭 가능한 요소를 감싸는 컨테이너에 **`data-noadvance`** 를 붙인다. 안 붙이면 전역 클릭 핸들러가 다음 슬라이드로 넘겨버린다.
- 내부 핸들러에서 **`e.stopPropagation()`** 를 반드시 호출한다. (실전 버그: 오버뷰 셀 클릭이 버블돼 내비 오발)
- 스크롤 영역은 `.scrollable` 클래스 필수(휠이 슬라이드 전환으로 새지 않게).
- `.phone` `.tablet` 은 이미 내비 억제 대상 — 그 안은 자유롭게 인터랙션 가능.
- 인터랙션은 **자기 완결적**이어야 한다: 클릭 → 상태 변화 → 되돌리기 가능. 다른 슬라이드 상태를 건드리면 안 된다.
- 상태 초기화: `section.addEventListener('slide:enter', reset)` 로 재진입 시 초기 상태 복원.

## 9. 목업(제품 UI 재현) 규율 — 이 덱의 핵심 자산

- 학생/선생님 화면을 재현할 때는 **RECON.md에 기록된 실제 색·라벨·레이아웃**을 쓴다. 상상으로 그리지 마라.
- 목업 내부는 제품 폰트(Pretendard) + 제품 회색 스케일(`--g50~--g900`) 사용. 덱의 dark 팔레트를 목업 안에 끌고 들어가지 마라.
- 목업 안의 데이터(학생 이름·점수 등)는 **제품의 정본 데모 fixture 값을 그대로** 쓴다.
  랜딩 데모와 세계관이 이어져야 시연 때 화면이 일치한다. 지문은 `The Gift of the Magi`,
  리포트 학생은 `김민준`(제품 fixture의 가상 학생), 학원명은 `SMOAT 영어학원`.
  fixture에 없는 새 학생·새 점수를 지어내지 마라. 추가 인원이 필요하면 `학생 A/B/C`.
- 목업 내부에 한해 이모지 사용 가능(제품이 실제로 쓰는 경우만).

## 10. 금지사항 (critical)

1. **COPY_SPEC.md에 없는 수치·명칭·기능 주장 추가** — 가장 심각한 위반.
2. 안전영역 침범(텍스트가 상 96 / 하 100 / 좌우 96 밖으로).
3. HUD·READOUT과 콘텐츠 겹침.
4. 전역 CSS 오염(`#sNN` 스코프 밖 셀렉터).
5. 토큰 밖 색 정의, 보라 그라데이션.
6. 외부 네트워크 자산 참조(CDN 폰트 3종은 template.html이 이미 로드 — 슬라이드에서 추가 로드 금지).
7. 존재하지 않는 이미지 경로 참조. **자산은 화이트리스트에 있는 것만.**
8. 이모지(제품 목업 내부 예외).
9. `AI가 만들어드립니다` 류의 도구 자랑 카피 — 서사 규율 위반(STORYLINE.md §6).
10. `alert()` `confirm()` `setInterval` 무한 부하, 외부 `fetch`.

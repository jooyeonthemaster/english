# SMOAT 세미나 덱 — 스토리라인 & 컨셉 확정서

> 이 문서는 **감독(본체) 직접 작성**. 팬아웃 에이전트는 이 문서를 규범으로 읽되 수정하지 않는다.

## 0. 컨셉 선언 (한 문장)

> **지문 한 장이 라인에 오르면, 문항·시험지·학습지·과제·리포트가 끝까지 흘러 — 다시 라인 입구로 돌아온다.**

SMOAT는 "AI 문제 생성기"가 아니라 **영어 내신 대비 제작 라인**이다.
강사가 여덟 개의 도구를 오가며 밤새 하던 공정이, 하나의 라인 위에서 흐른다.
그리고 이 라인은 **끝나지 않는다** — 학생이 푼 결과가 취약점이 되어 라인 입구로 되돌아온다.

이 덱의 무대는 **가동 중인 라인 그 자체**다. 청중은 라인 옆에 서서 재료가 흘러가는 것을 본다.

### 왜 이 컨셉인가 (판정 루브릭)
- **(a) 은유 강도** — 서비스의 실제 구조가 곧 라인이다. 억지 스킨이 아니라 구조의 번역.
- **(b) 내비게이션 지배** — 슬라이드 = 공정(STATION), 전환 = 이송, 오버뷰 = 공정도, HUD = 라인 계기.
- **(c) 데이터 장표 생존** — 리포트/취약점 장표도 "라인 후공정 계기판"으로 자연스럽게 흡수된다.
- **(d) 3초 인지** — 상단 레일에 노드가 한 칸씩 전진하는 것을 보는 즉시 "흐름"이 읽힌다.
- **(e) 사용자 핵심 요구 직결** — "흐름 자체가 전부 이해되어야 한다" → 하단 IN/OUT 계기가 **매 장표마다** 무엇이 들어가고 무엇이 나오는지 상시 표시한다.

## 1. 시각 어휘 사전

| 요소 | 컨셉 어휘 | 구현 |
|---|---|---|
| 슬라이드 단위 | **STATION (공정)** | `ST 07/27` — CH/PAGE 아님 |
| 상단 크롬 | **LINE RAIL** | 27노드 수평 트랙. 현재 노드 발광 + 지나온 노드 채움. 구간 라벨(투입·생성·산출·배포·회수·순환) |
| 우상단 계기 | **PART 칩 + 러닝 타임코드** | `● LIVE · PART 1 — 기능 브리핑` + `00:07:12` |
| 하단 크롬 | **MATERIAL READOUT** | `IN ▸ 지문 1장` — 화살표 — `OUT ▸ 25유형 문항` (슬라이드 `data-in`/`data-out`에서 자동 주입) |
| 전환 시그니처 | **컨베이어 어드밴스** | 좌→우 셔터 스윕(160ms) + 레일 노드 1칸 스텝 + 청사진 그리드 순간 발광 |
| 오버뷰 (G) | **LINE MAP (공정도)** | 격자 아님. 노드가 화살표로 이어진 흐름도 + ST08 → ST01 **회귀 루프 화살표**. 클릭 점프 |
| 배경 질감 | **청사진 그리드** | 96px 주격자 / 24px 부격자, opacity .04. dark 모드 |
| paper 모드 | **산출물 구역** | 시험지·학습지 등 실제 종이 산출물 장표. 미세 괘선 + 종이 그림자 |
| 진행 표시 | 레일 자체가 진행바 | 별도 프로그레스 바 없음 |

**금지**: CRT 스캔라인·TV 노이즈(다른 덱의 어휘), 보라 그라데이션, 이모지(제품 목업 내부 예외), 클립아트, Inter/Roboto/Arial.

## 4. 세미나 운영 사실 (확정 — 창작 금지)

- 총 **2시간**
- **1부 60분** = 기능 브리핑(이 덱, 약 10분) + 강사 라이브 시연(약 50분)
- **2부 60분** = 300크레딧 쿠폰 현장 등록 + 참가자 직접 실습
- 참가자 **전원 300크레딧** 제공
- 덱의 마지막 멘트: "**이제 직접 시연하는 시간을 갖겠습니다.**"

### 심장 슬라이드 4연타의 배치 의도
- **s05**(라인 공개) — 지도를 먼저 준다. 청중이 길을 잃지 않는다.
- **s16**(학생 태블릿) — 만져지는 증거. 세미나에서 가장 오래 머무를 장표.
- **s18**(리포트) — "어디서 어떻게 틀렸는지"의 실물. 강사가 지갑을 여는 지점.
- **s19**(루프 완성) — 서사의 정점. 라인이 원이 되는 순간.
- **s22**는 s05의 재림(완성형). 처음 본 지도가 전부 채워져 돌아온다.

### s23·s24(적중 블록)를 s22 뒤 · s25 앞에 둔 이유

s22까지는 "이 라인이 **무엇을 하는지**"를 보여줬다. 청중의 머릿속에 남는 마지막 질문은 하나다 —
**"그래서 이게 실제로 통합니까?"** 적중 블록은 정확히 그 자리에서 답한다.

> s22 라인이 한 바퀴 다 돌았습니다 → **s23 그런데 실제로 이런 일이 있었습니다(원본 캡처)**
> → **s24 왜 그런지 설명드립니다(구조)** → s25 그래서 300크레딧 드립니다 → s26 시연으로

**증거가 제안(크레딧)보다 반드시 앞선다.** 순서를 뒤집으면 s23이 영업 멘트로 읽히고 증거력이 죽는다.
s26("이제 직접 시연하는 시간을 갖겠습니다") 뒤로 보내는 것도 금지 — 닫은 서사를 다시 여는 꼴이다.

두 장은 한 몸이다. **s23(사실)만 쓰고 s24(이유)를 빼면 자랑이 되고, s24만 쓰고 s23을 빼면 가설이 된다.**

## 6. 서사 규율 (팬아웃 에이전트 필독)

1. **AI를 앞세우지 않는다.** "AI가 만들어줍니다"가 아니라 "선생님이 하시던 일이 라인 위에서 끝납니다".
   AI는 라인의 동력이지 주인공이 아니다. 주인공은 **강사의 시간**과 **학생의 성적**이다.
   → **유일한 예외: s24(WHY).** 이 장표는 주제 자체가 "학교와 우리가 같은 도구를 쓰기 시작했고,
     그래서 출제 자리가 겹친다"이므로 AI가 전면에 나온다. 단 **자랑이 아니라 원인 설명**으로만 쓰고,
     결론의 주어는 끝까지 **선생님**이다("선생님은 그 자리를 먼저 풀려두시면 됩니다").
     학교의 AI 출제는 **전언 인용**으로만 적고 덱이 사실로 단정하지 않는다. 상세: COPY_SPEC §0-적중.
2. **올인원임을 매 장표가 증명한다.** 하단 IN/OUT 계기가 앞 공정의 OUT = 이 공정의 IN 임을 보여준다.
3. **기능 나열 금지.** 모든 기능은 "선생님이 지금 겪는 불편 → 이 공정이 처리" 형태로 등장한다.
4. **숫자·명칭 창작 절대 금지.** COPY_SPEC.md에 등재된 자구만 사용. 스펙 밖 수치 추가 = critical.
5. **말투**: 세미나 현장에서 강사가 직접 말하듯. 과장 광고 톤 금지, "혁신/혁명/게임체인저" 금지.
   짧은 문장. 조사 생략하지 않기. 마침표 있는 완결형과 명사형 종결을 섞어 리듬을 만든다.
6. **후킹 문구는 적재적소 1개씩.** 장표당 최대 1개. 남발하면 전부 죽는다.

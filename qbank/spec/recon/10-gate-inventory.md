### 게이트 3대 구조 패턴 (전 유형 공통)
1. **조기반환(early return)** — 개수·형상이 어긋나면 **한 줄만** 돌려주고 나머지 검사를 전부 침묵한다.
   → 게이트 출력이 1줄이면 "결함이 1개"가 아니라 **"그 이후를 못 봤다"** 는 뜻이다. 재저작 시 착각 금지.
2. **지문 재구성 대조** — 마커/조각을 원형으로 되돌린 결과 == `normalizeWs(passage)`. 지문 변형형의 최강 불변식.
3. **`정답:` 줄 유일 진실원** — 선지 줄·해설에 정답 표시를 두면 별도 코드로 반려된다(철칙 1).

## §3 ★ 유형별 지문 적합성 규칙 (10만 유닛 계획의 근거)

### 3.0 결론 먼저 — **`feasibility.ts` 는 거의 비어 있다**

임무 가설("유형별 지문 적합성 판정이 feasibility.ts 에 있을 것")은 **틀렸다**.
`src/lib/question-quality/feasibility.ts` 는 **전체 62줄**이고, `preflightQuestionFeasibility` 가 판정하는 유형은
**`SENTENCE_ORDER` 하나뿐**이다. 나머지 25유형은 `return { ok: true }`(`feasibility.ts:61`).

```
feasibility.ts:32   if (typeId === "SENTENCE_ORDER") { ... }
feasibility.ts:61   return { ok: true };            // 그 외 전 유형·전 난이도 무조건 통과
```

파일 헤더가 그 이유를 명시한다(`:17-26`):
> "SHIP-FIRST 사전 적합성 게이트 — 차감 전에 **기계적 불가능**만 빠르게 거른다.
> ⚠️ 출제 포인트의 품질/적합성 판단은 절대 여기서 하지 않는다. …
> **현재 SENTENCE_ORDER 만 활성**. 그 외 모든 유형/난이도는 ok(기본 개방).
> 난이도는 시그니처에만 받아두고 게이트하지 않는다(KILLER를 불가로 취급 금지)."

**→ 진짜 지문 적합성 규칙은 (a) 게이트 본문, (b) 레인 parseAndGate, (c) 어댑터·후처리 하드실패 에 흩어져 있다.**
아래가 그것을 전수 수집한 결과다. **이것이 유닛 계획의 유일한 근거다.**

### G1 [치명] `lane.isEligible` 을 **한 번도 호출하지 않는다**

`gateUnit`(`qgen-core.ts:200-377`)·`buildProductionPrompt`(`:140-156`) 어디에도 `isEligible` 호출이 없다.
프로덕션 라우트는 이 검사로 `MD_STREAM_INELIGIBLE` 을 내고 fast 로 폴백한다.

→ **결과**: `settings` 에 범위 밖 값(`{"genericOptionCount": 12}`·`{"grammarMarkerCount": 3}`)을 써도
하네스는 그대로 진행하고, 게이트가 엉뚱한 사유(`선지 12개 (12개 필요)` 통과 후 품질에서 `option-count`)를 낸다.
**수정**: `buildCtx` 직후 `lane.isEligible(ctx.resolved)` 를 호출하고 실패 시
`blocking.push({item, code:"INELIGIBLE_SETTINGS", ...})`.

### G2 [치명] `shuffleQuestionOptionsForDiversity` 가 **빠졌다**

`00-contract.md §2·§10` 이 명시한 시퀀스는 `postProcess → 메타부착 → shuffle → validateQuestionQuality` 다.
`qgen-core.ts:283-295` 는 `postProcess → validateQuestionQuality` 로 **셔플을 건너뛴다**.

→ **결과 2가지**:
1. 라벨 재매핑 후에만 드러나는 결함(해설-라벨 desync)을 못 본다.
2. **셔플이 조용히 포기되는 사고를 탐지할 수 없다.** `question-diversity.ts` 의 `UNMAPPABLE_MENTION` 이
   해설에서 평숫자 지칭을 발견하면 재배열을 통째로 건너뛴다 — 게이트 3종(`gate-topic-main-idea.ts:192` ·
   `gate-synonym.ts:359` · `gate-context-meaning.ts:252`)만 이걸 막고 **나머지 21유형은 무방비**다.
**수정**: `shuffleQuestionOptionsForDiversity(data, subType)` 를 삽입하고, 셔플 전후 라벨 매핑이
   실제로 바뀌었는지(=포기되지 않았는지) `blocking` 으로 판정.

### G3 [높음] `analyzeEnglishPassageIntegrity` 를 **유닛마다 5~8회 중복 실행**한다

이 함수는 `validateQuestionQuality` 내부에서 문항마다 호출된다(`dispatcher.ts:790-794`).
지문은 유닛 전체에서 하나인데, 오염된 지문이면 **같은 사유가 문항 수만큼 `qualityBlocking` 에 쌓인다.**
4,537 지문 × 26유형 × 5~8문항 규모에서는 **지문 1개 오염 = 최대 208건 중복 차단**.

→ **수정**: 유닛 진입 전에 `analyzeEnglishPassageIntegrity(passage)` 를 **1회** 돌려
`blocking.push({item:null, code:"PASSAGE_INTEGRITY", ...})` 로 조기 종료. 나아가 **4,537 지문 전수 사전 스크리닝**
(`qbank/harness/passage-screen.mjs` 에 이 검사가 **없다** — 실측 확인).

### G4 [높음] `preflightQuestionFeasibility` 미호출

`feasibility.ts:27` 의 `SENTENCE_ORDER` 4문장/40단어 하한이 하네스 어디에서도 실행되지 않는다.
`IRRELEVANT` 는 `lane-irrelevant.ts:182` 가 `parseAndGate` 안에서 자체 호출하므로 커버되지만,
`SENTENCE_ORDER` 는 **저작을 다 한 뒤에야** 게이트 `#1 단락 3개`·`#6 무손실 분할`에서 죽는다.

→ **수정**: `gateUnit` 진입 시 `preflightQuestionFeasibility(subType, difficulty, passage)` 호출.
   더 중요하게는 **유닛 계획 단계(`plan.mjs`)에서 §3.7 매트릭스를 적용해 애초에 유닛을 만들지 마라.**

### G5 [중간] 난이도 분포(§4 헌법)를 검사하지 않는다

`quality-constitution.md:128-133` 은 "5문항: BASIC 1 / INTERMEDIATE 2 / KILLER 2, 전량 KILLER·전량 BASIC 금지"를
규범으로 정했는데 `gateUnit` 은 `difficulty` 를 `ctx` 로 넘길 뿐 **분포를 보지 않는다**.
`POINT_DUPLICATE`·`ANSWER_DUPLICATE` 와 같은 자리(유닛 단위 검사, `:335-363`)에 넣어야 한다.

→ **수정**: `DIFFICULTY_DISTRIBUTION` 코드 추가.

### G6 [중간] `craft` 필드를 요구하지 않는다

`splitItems` 는 `point` 누락만 검사하고(`:93`) `craft` 는 `raw.craft || ""` 로 조용히 비운다(`:101`).
`ItemMeta.craft` 가 헌법 §7 다각화 추적의 절반인데 강제가 없다.

### G7 [중간] `POINT_DUPLICATE` 정규화가 과도하다

`normalizePoint`(`:389-394`)는 `[^\p{L}\p{N}]+` 를 공백으로 바꾸고 소문자화만 한다.
`"인과 기제 — 원인과 결과"` 와 `"인과기제: 원인과 결과"` 는 **같은 키**로 접혀 중복 차단된다(의도된 동작).
반대로 `"인과 기제(도입)"` vs `"인과 기제(결론)"` 은 **다른 키**라 통과한다 — 의미 중복은 못 본다.
헌법 §7 이 "게이트는 문자열 수준만 본다"고 이미 인정했으므로 **버그는 아니나** 검수 렌즈 ⑤ 의존도가 크다.

### G8 [낮음] `ITEM_HEADER` 정규식이 한 줄 헤더를 못 읽는다

`ITEM_HEADER = /<!--\s*ITEM\s+(\d+)\s*\n([\s\S]*?)-->/g` (`:57`) — **번호 뒤 개행 필수**.
`<!-- ITEM 1 difficulty: KILLER -->` 처럼 한 줄로 쓰면 헤더가 하나도 안 잡혀
`ITEM 헤더가 하나도 없다` 로 전량 반려된다. 저작 지침에 개행을 명시하라.

### G9 [낮음] 필드 키 정규식이 ASCII 전용

`/^\s*([A-Za-z_][A-Za-z0-9_]*)\s*:\s*(.*)$/` (`:78`) — 한글 키(`포인트:`)는 무시된다.
`point:` `craft:` `difficulty:` `settings:` 만 유효.

### G10 [낮음] `mergeSettings` 가 **`base` 가 배열일 때** 오동작 가능

`:381` 이 `typeof base === "object"` 로만 판정해 배열도 스프레드한다. 실무상 `null` 만 들어오므로 무해. **[미상: 실사용 경로]**

### G11 [정보] `00-contract.md:148` 의 서술이 낡았다

> "정본 2종은 별도 분기 필요(현재 `UNSUPPORTED_LANE` 로 차단 중 — 조용한 통과 방지)"

**현재는 사실이 아니다.** `qgen-core.ts:24-26` 이 `getRegistryLane(subType) ?? getCanonLane(subType)` 로
`canon.ts` 를 합류시켜 **26유형 전부 지원**한다. `UNSUPPORTED_LANE` 은 이제 오타·미지 유형에만 뜬다.

### G12 [정보] `TITLE`·`ANTONYM` 게이트는 `gate-*.ts` 밖에 있다

`gate-title.ts`·`gate-antonym.ts` 는 **존재하지 않는다**. 각각 `parser-title.ts:305`·`parser-antonym.ts:171` 이다.
게이트 커버리지를 파일 글롭으로 자동 검사하는 스크립트를 쓰면 두 유형이 조용히 빠진다(§1.4·§1.12 에 전수 수록 완료).

### 하네스가 **올바르게** 하고 있는 것 (회귀 방지용 기록)

- `blocking` / `qualityBlocking` **축 분리**(`:186-194`) — 웹 통과율과 혼동 방지. 설계대로다.
- `lane.filterQualityIssues` 적용(`:296-300`) — 레인이 선언한 오탐 축을 존중.
- 게이트 실패 시 어댑터를 **호출하지 않음**(`:278`) — 프로덕션과 동일(파생 잡음 차단).
- `corrections`(오토스냅)를 `warnings` 로 분리(`:323`) — 조용한 보정을 은폐하지 않음.
- `diversityTargets` 예외 삼킴(`:304-308`) — 다양성 추출 실패가 문항을 죽이지 않음.
- 파이프라인 예외를 `gateIssues` 로 흡수(`:312-314`) — 크래시 대신 반려.

## §6 저작 에이전트용 최소 체크리스트 (전 유형 공통)

1. **장식 0.** 굵게·헤딩·불릿·인용·표 파이프·백틱을 머리표·선지·값 줄에 쓰지 마라(`00-contract.md §8`).
   - 표 파이프는 `gate-reference.ts:105` · `gate-summary-mc.ts:322` · `gate-conditional-writing.ts:65` 가 각각 잡는다.
2. **정답 채널은 하나.** `정답:` 줄 외 어디에도 정답 표시를 두지 마라 — 4개 게이트가 각기 다른 정규식으로 잡는다
   (`gate-topic.ts:39` · `gate-topic-main-idea.ts:46` · `gate-main-idea.ts:59` · `gate-combo.ts:426`).
3. **해설에 번호 지칭 금지.** `1번`·`(2)`·`선지 3`·`①~③` 은 셔플을 죽이거나(3유형) 문항을 무효화한다(2유형).
4. **해설은 한국어만.** 한자·가나 금지, `영단어+다` 금지, 영어 인용은 따옴표 안 + **문항 표면에 실재하는 것만**.
5. **인용은 12자 미만이면 안 걸리고, 12자 이상이면 반드시 실재해야 한다**(`explanation-quoted-tokens.ts:37`).
6. **지문 변형형은 재구성 대조를 통과해야 한다.** 마커 밖 1글자도 바꾸지 마라.
7. **표적은 지문에서 1회만 등장해야 한다** — 어휘·함축·지칭·빈칸 계열 공통.
8. **유닛 안에서 `point:` 는 전부 달라야 하고, 정답 표적도 전부 달라야 한다**(`qgen-core.ts:337,357`).
9. **컨테이너 헤더는 `<!-- ITEM n` 뒤에 반드시 개행**(`qgen-core.ts:57`).

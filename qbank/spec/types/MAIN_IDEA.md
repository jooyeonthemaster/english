## 1. 정체성 — 이 유형이 학생에게 요구하는 인지 작업

**"이 글이 무엇에 대한 글인가"(주제)가 아니라 "그 소재에 대해 필자가 내린 판단·권고"를 고르게 한다.**
소재만 옮긴 진술은 요지가 아니라 주제이며 그건 `TOPIC` 유형의 표면이다 — `prompts-main-idea.ts:240`.

- **읽어야 풀리는 것**: 논지 전개(통념 제시 → 반박 → 근거 → 귀결)의 **전환 지점 이후**. `however·but·yet·rather·in fact` 뒤가 요지의 자리이고, 전환이 없으면 마지막 한두 문장의 귀결이 요지다 — `prompts-main-idea.ts:241`.
- **첫 문장은 대개 소재 도입이지 요지가 아니다** — `prompts-main-idea.ts:242`. 도입부를 요지로 승격한 진술이 이 유형의 2번 오답 기제(`도입부함정`)다.

### 인접 유형과의 경계 (게이트가 결정형으로 집행하는 것)

| 축 | MAIN_IDEA | 인접 유형 |
|---|---|---|
| 선지 형상 | **완전한 한국어 진술문**(어미 `다/음/함/됨/해야/필요/중요/가능/있다/없다/된다/준다`로 끝남) | `TITLE`·`TOPIC` = 명사구 |
| 게이트 집행 | 명사구가 `max(3, optionCount-1)`개 이상이면 **error 반려** — `gate-main-idea.ts:44,157-161` | — |
| 선지 기본 언어 | **ko** (`language.ts:20`) | `TOPIC`·`TITLE` 은 en |
| 발문 | 어댑터가 결정형 생성(모델이 쓰지 않는다) — `adapter-main-idea.ts:51-78` | — |
| 지문 | **한 글자도 변형하지 않는다**(PASSTHROUGH) | 빈칸·어법·순서 계열은 변형 |

### 이 유형만의 구조적 특징 — `근거:` 줄

지문을 변형하지 않으므로 **다른 유형의 최강 게이트인 "지문 재구성 일치"가 존재하지 않는다** — `gate-main-idea.ts:13-16`.
그 자리를 대신하는 것이 `근거:` 줄이다. 정답 논지가 가장 압축된 **지문 문장 하나를 축자 복사**한 줄이고,
게이트 #7 이 이 줄만 지문과 대조한다. **이 유형에서 문항과 지문을 잇는 유일한 결정형 앵커다.**
`근거:` 는 저장되지 않는다(어댑터가 버린다 — `adapter-main-idea.ts:22-23`). 즉 학생에게 보이지 않는, **오직 기계 검증과 저작 공예를 위한 줄**이다.

## 3. 파서 계약 (★ 가장 중요)

> **원칙**: 파서는 관대하고 게이트는 엄격하다 — `parser-main-idea.ts:4`.
> 아래 "관용"은 **사고 방지용 안전망이지 저작 허가가 아니다.** qbank 저작 규칙은 계약 §8 대로 **장식 0**.

### 3-1. 키워드 줄 머리 정규식 (5종 공통)

`parser-main-idea.ts:78` — `KEYWORD_WORDS = ["발문형", "근거", "정답", "해설", "오답"]`
`parser-main-idea.ts:86-94` — `keywordHead(word)` 가 만드는 소스(캡처 그룹 없음, `String.split` 에 쓰이므로 캡처 금지):

```
^[ \t]*(?:>[ \t]*)*(?:#{1,6}[ \t]*)?(?:[-*+•][ \t]+)?(?:\*\*|__|\*|_)?[ \t]*<WORD>[ \t]*(?:\*\*|__|\*|_)?[ \t]*(?:[:：][ \t]*(?:\*\*|__|\*|_)?[ \t]*|(?=[ \t]*$))
```

| 흡수하는 드리프트 | 예 |
|---|---|
| 인용 `>` 반복 | `> 근거: …` |
| 헤딩 `#`~`######` | `### 정답: ①` |
| 불릿 `- * + •` | `- 정답: ①` |
| 굵게·기울임 `** __ * _`(머리·꼬리 각 1개) | `**정답:** ①`, `**정답**: ①` |
| 전각 콜론 `：` | `정답： ①` |
| 콜론 생략 + 값이 다음 줄 | `### 정답`↵`①` |

- **어길 때 사라지는 것**: 위 목록 **밖**의 장식(예: 백틱 `` `정답:` ``, 표 파이프 `| 정답 | ① |`)을 머리표에 쓰면 그 줄이 키워드로 인식되지 않는다 → `정답:`/`오답:` 앵커 동시 실종 시 게이트 #0 이 즉시 단일 반려.
- **`m` 플래그**로 컴파일된다 — `parser-main-idea.ts:96-97`. CRLF 개행 안전(프로브 D11 실측 클린).

### 3-2. 값이 같은 줄에 있어야 하는 머리표 — `발문형:` / `근거:`

`parser-main-idea.ts:100-103`
```
VALUE_TAIL   = "(\\S[^\\r\\n]*)$"
RE_STEM      = keywordHead("발문형") + VALUE_TAIL
RE_EVIDENCE  = keywordHead("근거")   + VALUE_TAIL
```
- 값의 **첫 글자가 공백이 아니어야** 캡처된다. 콜론 뒤 공백은 `keywordHead` 의 `[ \t]*` 가 이미 먹는다.
- **★ 비대칭**: `### 근거`↵`문장` 처럼 **값을 다음 줄로 내리면 캡처가 실패**한다(`VALUE_TAIL` 이 줄 끝에서 비어 있음).
  → `근거 문장 누락` 으로 반려된다(프로브 D10 실측). `### 정답`↵`①` 은 반대로 흡수된다(D10b). **헤딩형은 `정답:` 에서만 통한다.**
- **어길 때 사라지는 것**: `근거:` 값 → 게이트 #7 「근거 문장 누락」. 지문 정합 앵커 소실 = 문항 폐기.

### 3-3. 섹션 앵커와 선지 구간 절단

`parser-main-idea.ts:104-105, 229-233`
```ts

const ANCHOR_WRONG  = keywordLine("오답");
```

### 3-5. `정답:` 줄 파싱

`parser-main-idea.ts:196-205, 237`
```ts
firstValueLine(answerSplit[1] ?? "")            // 앵커 뒤 첫 비어있지 않은 줄(키워드 줄이면 "")
```

### 3-6. `해설:` 파싱

`parser-main-idea.ts:106-110, 245-249`

| `requireWrong`(게이트) | boolean | `true` | 레인이 넘기지 않음 → **항상 true** | `오답:` 섹션은 언제나 필수 |

**`isEligible`**(`lane-main-idea.ts:87-99`): `4 ≤ optionCount ≤ 8` **그리고** `1 ≤ answerCount ≤ optionCount-1`. 벗어나면 유형 자체가 실행되지 않는다.

> ⚠ **리졸브 후 이름(`genericOptionCount`/`genericAnswerCount`)을 `settings:` 에 쓰면 조용히 무시된다.**
> 프로브 B3 실측: `{"genericOptionCount":6}` + 6선지 → `선지 6개 (5개 필요)` 반려. 반드시 `optionCount` 를 써라.

## 7. 함정

전부 프로브(`qbank/work/_probe-MAIN_IDEA.ts`) 또는 픽스처(`scripts/_test-md-main-idea.ts`)로 재현 확인한 것만 적는다.

### T1 — 선지 구간에 산문 한 줄 (★ 조용히 통과하는 오염)
선지 ①~⑤ 사이나 ⑤ 뒤·`정답:` 앞에 설명 한 줄을 넣으면 **직전 선지에 이어 붙고 게이트는 클린**이다.
프로브 D1: `⑤ 이용자는 알고리즘이 고른 자료를 신뢰하지 않는다. 이상 다섯 선지는 모두 지문 소재로 만들었습니다.` 가 그대로 저장됐다.
근거 `parser-main-idea.ts:182-187`. → **선지 구간에는 라벨 줄만 쓴다.**

### T2 — 줄 순서를 바꾸면 선지가 부푼다
`정답:` 을 `오답:` 뒤로 옮기면 선지 구간이 오답해설을 삼켜 `선지 9개 (5개 필요)` 로 죽는다(프로브 D2).
근거 `parser-main-idea.ts:229-233`. → **`발문형: → 근거: → 선지 → 정답: → 해설: → 오답:` 순서는 계약이다.**

### T3 — 문서 끝에 무엇을 더 쓰면 마지막 오답해설이 오염된다
`오답:` 이후 어떤 줄이든(지문 재출력, 설계 메모, 인사말) 마지막 오답해설에 흡수되고 게이트는 통과한다.
프로브 D4: `## 지문` + 지문 전문 434자가 ⑤ 오답해설에 붙었다. → **마지막 오답해설 줄이 문서의 마지막 줄이다.**
(참고: `## 지문` 은 프롬프트 입력이지 모델 출력이 아니다 — 계약 §4.)

### T4 — `### 근거` 헤딩형은 근거를 통째로 날린다
`정답:` 은 헤딩형(값이 다음 줄)이 흡수되지만 `근거:`·`발문형:` 은 **같은 줄에 값이 있어야 한다**(`VALUE_TAIL`).
프로브 D10: `근거 문장 누락` 으로 반려. 근거 `parser-main-idea.ts:100-103`. → **장식 0. 값은 항상 같은 줄에.**

### T5 — 선지 본문의 파이프 `|`
`cleanOptionText` 가 `\s*\|+.*$` 를 잘라낸다(`parser-main-idea.ts:148`). 선지에 `A | B` 를 쓰면 `B` 가 사라지고,
잘린 꼬리가 연결어미면 게이트 #6 「문장으로 끝나지 않음」이 뜬다. → **선지에 파이프 금지.**

### T6 — 선지를 두 줄로 접기
이어짐 관용이 대개 붙여 주지만, 뒷줄이 유실되면 `…것일 뿐이며,` 처럼 **쉼표·연결어미로 끝난 미완성 정답 선지**가 나온다.
게이트 #6(`TRUNCATED_TAIL`)이 라벨로 지목한다 — `gate-main-idea.ts:76-77,139-143`. → **선지는 개행 없이 한 줄.**

### T7 — 선지 줄에 정답 표시
`(정답)` `← 정답` `✅` 등은 스냅이 걷어내지만 `corrections` 경고가 남고, 스냅이 모르는 변형(`(정답 선지임)`, 줄 앞머리 `정답 …`)은
게이트 #5 로 반려된다(`_test-md-main-idea.ts:306-325`). **정답의 진실원은 `정답:` 줄 하나뿐이다.**
(반대로 `학생은 정답을 맞히는 능력보다…` 처럼 조사가 붙은 본문 어휘는 통과한다 — 오반려 방지 가드.)

### T8 — 명사구 선지 (제목·주제형 표면)
5선지 중 **4개 이상**이 `KO_STATEMENT_TAIL`(`다/음/함/됨/해야/필요/중요/가능/있다/없다/된다/준다`)로 끝나지 않으면 게이트 #9.
프로브 D5: 3개는 통과, 4개는 `해당 ②③④⑤` 로 반려. → **선지는 전부 완결 진술문.** `…의 중요성`·`…에 대한 고찰` 금지.

### T9 — 선지 길이 불균형
`최장-최단 > 30자` **그리고** `최장 ≥ 최단×2` 를 **동시에** 만족하면 반려(`gate-main-idea.ts:186`).
둘 중 하나만이면 통과하므로 게이트를 믿지 말고 §3 헌법 운용규칙 6(층위 일치)을 지켜라.

### T10 — 선지 포함관계 (종결부호만 다른 쌍)
`foldKey` 가 공백·구두점을 지우므로 `…넓혀 준다.` 와 `…넓혀 준다는 점이 중요하다.` 는 포함관계로 잡힌다(`:172-178`, 픽스처 `:148`).
→ **한 문장을 늘여 쓴 선지 2개 금지.** 서로 배타적인 명제여야 한다.

### T11 — 정답 선지 = 근거 문장 축자 복사
게이트 #20 이 잡는다(foldKey 상호 포함, 길이 ≥ 20). **단 선지가 한국어이고 근거가 영어면 못 잡는다**(프로브 D9 실측 — 게이트 사각).
근거 문장의 한국어 직역을 정답으로 쓰면 **기계는 통과하지만 헌법 §9-3(축자 복사)에 걸려 F 판정**이다. → 정답은 반드시 **재진술/추상화**.

### T12 — 오답 목록에 정답 라벨 줄 끼워넣기
파서가 버리고(`:243`) 게이트 #24·#28 이 `오답해설 3개 (4개 필요)` + `② 오답해설 누락` 으로 이중 반려(프로브 D6).
→ **오답해설은 비정답 라벨만, 정확히 `optionCount - answerCount` 개.**

### T13 — 해설 언어
게이트 #22 는 한글이 **하나라도** 있으면 통과시킨다(`HANGUL_RE.test`). 즉 영어 혼입을 막지 못한다.
헌법 §5 언어 규약(한국어만·합니다체·비한글 CJK 금지·`steals다` 류 금지)은 **검수 렌즈가 잡는다.** 게이트 통과를 근거로 삼지 마라.

### T14 — `settings:` 키 이름
`genericOptionCount` 를 쓰면 무시된다(프로브 B3). → `optionCount`/`answerCount`/`answerPolarity`/`optionLanguage`/`stemLanguage`.

### T15 — 유닛 `ANSWER_DUPLICATE` (저작으로 해결 불가)
§4-C 참고. **마크다운을 어떻게 써도 유닛 `ok` 는 false 다.** 저작 에이전트는 이것을 자기 결함으로 오인해 재작성하지 마라.

## 8. 출제 포인트 다각화 축

> **전제**: 한 지문의 요지는 하나다. 5~8문항의 "정답이 말하는 명제"는 **불가피하게 같은 논지**다.
> 따라서 이 유형의 다각화는 **"정답이 무엇인가"가 아니라 "어느 근거로 그 정답에 도달하는가 + 어떤 오답을 뚫어야 하는가"** 에서 나온다.
> 레인 자신이 이 점을 못박고 있다 — `lane-main-idea.ts:178-191`: *"한 지문의 요지는 하나뿐이라 '이전 정답을 피하라'는 지시는 곧 '틀린 요지를 골라라'가 된다"*.
> **정답 진술을 서로 다르게 만들려고 논지를 비틀면 그 순간 오답 문항이다.** 이게 이 유형 다각화의 제1 제약이다.

- `point:` 는 위 표의 **D1+D2 를 한 줄로 합쳐** 쓴다(예: `전환 직후 귀결 종합 — however 뒤 문장과 체감 문장을 이어야 도출`). 유닛 내 전부 달라야 `POINT_DUPLICATE` 를 피한다.

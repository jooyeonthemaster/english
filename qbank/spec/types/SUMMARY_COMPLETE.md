## 1. 정체성 — 이 유형이 학생에게 요구하는 인지 작업

지문 전체를 **영어 한 문장으로 압축한 요약문**이 주어지고, 그 문장의 빈칸 `(A)`(설정에 따라 `(B)`~`(E)`)에 들어갈 **영어 단어·짧은 어구를 학생이 손으로 직접 써 넣는다**. 발문은 `다음 글의 내용을 한 문장으로 요약하고자 한다. 빈칸에 들어갈 말을 쓰시오.` — `adapter-summary-complete.ts:36-37`.

학생이 실제로 하는 일은 네 겹이다.

1. **지문 전체의 논지·인과 축을 하나로 접기** — 요약문이 지문 어느 한 문장이 아니라 글 전체의 압축이므로, 부분만 읽으면 어느 칸도 확정되지 않는다.
2. **추상화 1단계 번역** — 정답은 지문 표면어의 복사가 아니라 상위 개념이다. 지문에 통째로 있는 어구는 게이트가 결정형으로 차단한다(`gate-summary-complete.ts:93-106, 296-302`).
3. **문법 슬롯 복원** — **선지가 없다.** 학생이 쓴 문자열이 EXACT 로 대조되므로(`answer-spec.ts:303-305` → `grade.ts`), 요약문의 빈칸 앞뒤 구조가 답의 품사·수·시제를 구속하지 않으면 답이 수렴하지 않는다. **이 유형에서 문법 슬롯 설계는 장식이 아니라 채점 가능성의 조건이다.**
4. **산출(production)** — 고르는 게 아니라 쓴다. 재인(recognition)이 아니라 인출(recall)이라 같은 논지를 물어도 MC 판보다 항상 어렵다.

### 다른 유형과의 경계

| 축 | **SUMMARY_COMPLETE** | 인접 유형 |
|---|---|---|
| 빈칸이 있는 곳 | **저작자가 새로 쓴 요약문 한 문장** | `BLANK_INFERENCE`: **지문 본문**의 표현을 삭제 |
| 지문 | 한 글자도 안 건드림(PASSTHROUGH) | `BLANK_INFERENCE`·`VOCAB_CHOICE`: 지문 변형 후 재구성 대조 게이트 |
| 응답 형식 | **서술형 — 선지 없음. 학생이 영어를 쓴다** | `SUMMARY_COMPLETE_MC`: 값 조합 5지선다 |
| 정답의 진실원 | **`정답(A):` 라벨별 줄**(빈칸마다 한 줄) | `SUMMARY_COMPLETE_MC`: `정답: ③` 한 줄에서 값을 파생 |
| `오답:` 블록 | **존재하지 않는다** | 객관식 전반: 필수 |
| 채점 | `blanks[].label` 이 입력 키, `acceptedAnswers` 가 EXACT 허용 집합, 칸별 부분점수 | MC: 선지 라벨 단일 대조 |
| 정답 길이 | **5단어 이하**(권장 1~3) | `SUMMARY_WRITING`: 빈칸당 목표 7단어대 영작 |
| 동치 관리 | **`허용답(X):` 줄이 유일 통로** — 여기 적힌 것은 자동채점 **무조건 만점** | MC: 동치 개념 자체가 없음 |

### 이 유형이 죽는 지점

- **요약문이 지문 문장의 재배열이면 실격.** 연속 8토큰 복사를 결정형으로 잡는다(`gate-summary-complete.ts:36, 66-81, 240-245`).
- **정답을 두 곳에 적으면 죽는다.** `모범답안:` 줄도, `허용답:` 안의 정답 자기복제도 계약에 없다(`prompts-summary-complete.ts:14-20`). 진실원은 `정답(X):` 줄 하나.
- **`허용답:` 은 이 유형에서 가장 위험한 칸이다.** 여기 적힌 문자열은 채점에서 아무 필터 없이 만점 집합에 주입된다(`adapter-summary-complete.ts:23-25`, `answer-spec.ts:196-216`). 오답 하나를 잘못 넣으면 되돌릴 수 없다.
- **정답에 대안을 나열하면 아무도 못 맞힌다.** `untrained/unpracticed` 는 그 문자열 **전체**가 유일 정답이 된다(EXACT). 게이트가 슬래시·쉼표·세미콜론·`or`·`(or …)`·`또는` 을 전부 차단한다(`gate-summary-complete.ts:150-163`).

### 3-1. 줄 장식 제거 — `stripLineDecoration` (`:97-115`)

```ts
line
  .replace(/^\s*\|\s*/, "")            // 선행 표 파이프 1개
  .replace(/\s*\|\s*$/, "")            // 후행 표 파이프 1개
  .replace(/\*+/g, "")                 // 별표 강조 — 개수 무관 전부 제거
  .replace(/^\s*(?:[-•·]|\d+[.)])\s+/, "")   // 불릿 / 번호 접두 (뒤에 공백 필수)
  .replace(/^[[【]\s*([^\]】]{1,16})\s*[\]】]\s*/, (full, inner) =>
     HEAD_KEYWORD_RE.test(inner.trim()) ? inner.trim() : full)   // [해설]: 포장 벗기기
  .trim()
```
`HEAD_KEYWORD_RE = /^(?:요약문|정답|허용\s*답(?:안)?|허용\s*정답|동치|해설)/` — `:95`

헤딩은 별도 처리(`:208-211`): `/^#{1,6}\s/` 이면 `#` 을 벗기고 **장식 제거를 한 번 더** 돌린다.

| 흡수되는 것 (써도 통과) | 흡수 **안 되는 것** |
|---|---|
| 선/후행 파이프 `\| 정답(A) \| x \|` | **인용 `>`** — 분기가 아예 없다 |
| 별표 `**정답:**` `*정답:*` `***정답:***` | 불릿 뒤 공백 없음 `-정답(A):` |
| 불릿 `- ` `• ` `· ` , 번호 `2. ` `2) ` | 라벨이 2글자 이상 |
| 헤딩 `## ` ~ `###### ` (복합 `## - **정답(A):**` 포함) | 대괄호 포장 안 내용이 17자 이상 |
| 대괄호 머리표 `[해설]:` `【해설】:` `[정답(A)]:` | |

> ★ **`> 요약문:` 처럼 인용 부호를 붙이면 그 줄이 통째로 사라지고 「요약문 누락」이 뜬다**(프로브 E1'/E1''/E1''' 실증). `밑줄(_)` 도 벗기지 않는다 — 요약문의 `_____` 잔존은 게이트가 잡아야 하기 때문(`:105` 주석).

### 3-2. 머리표 정규식 4종 (`:117-126`)

```ts
const SEP   = "\\s*[:：|]\\s*";
const LABEL = "\\s*[(（\\[]?\\s*([A-Za-z])?\\s*[)）\\]]?\\s*";

const HEAD_SUMMARY     = new RegExp(`^요약문${SEP}(.*)$`);
const HEAD_ANSWER      = new RegExp(`^정답${LABEL}${SEP}(.*)$`);
const HEAD_ACCEPTED    = new RegExp(`^(?:허용\\s*답(?:안)?|허용\\s*정답|동치)${LABEL}${SEP}(.*)$`);
const HEAD_EXPLANATION = new RegExp(`^해설${SEP}(.*)$`);
```

| 축 | 계약 |
|---|---|
| 구분자 | 반각 `:` · **전각 `：`** · **파이프 `\|`** 셋 다 인정. **콜론 생략 불가** |
| 라벨 표기 | `(A)` `（A）` `[A]` `A` · **소문자 `(a)` 가능**(`summaryCompleteParenLabel` 이 대문자로 접음 `:50-58`) · 라벨 앞뒤 공백 가능 |
| 라벨 범위 | `A`~`E` 만(`SUMMARY_COMPLETE_MD_LABEL_KEYS = "ABCDE"`, `prompts-summary-complete.ts:26`). 범위 밖 1글자는 **빈 문자열**로 접혀 라벨 없음 취급 |
| 허용답 머리표 별칭 | `허용답` `허용 답` `허용답안` `허용 답안` `허용정답` `허용 정답` `동치` — **전부 인정**(프로브 P7-5 실증) |
| 값 접힘 | 머리표만 있고 값이 비면 `pending` 이 되어 **바로 다음 비어있지 않은 줄 하나**를 값으로 먹는다(`:216-223, 232-238, 268-272`) |

> ★ **`pending` 은 딱 한 줄만 먹는다.** 요약문을 두 줄로 쓰면 **둘째 줄이 조용히 사라진다**(프로브 P7-1). 요약문은 반드시 한 줄.

**어기면**: 머리표를 인식 못 하면 그 필드가 통째로 빈 값이 되고, 게이트가 「요약문 누락」·「정답(B) 줄을 인식할 수 없음」·「해설 누락」이라는 **사실과 다른 원인**을 재생성 피드백으로 실어 보낸다(`:90-92` 주석).

### 3-3. 값 정제 — `firstCell` (`:141-145`)

```ts
const cell = raw.split("|").find((seg) => seg.trim().length > 0) ?? "";
return cell.replace(/\s+/g, " ").trim();
```

- 값 안에 파이프가 있으면 **첫 비어있지 않은 칸만 남고 나머지는 조용히 버려진다.**
- ★ `정답(A): unsettles | 흔든다` → `unsettles` 로 **절단되고 게이트는 클린**이다(프로브 P7-7). 한국어 주석을 파이프로 붙이는 습관이 이 유형에서만 무음으로 통과한다.

### 3-4. 허용답 목록 분해 — `splitAcceptedList` (`:152-159`)

```ts
cleaned.split(/\s*[,;，、]\s*|\s+\/\s+/)
```

| 인식되는 구분자 | 비고 |
|---|---|
| `,` `;` `，` `、` (앞뒤 공백 무관) | **계약 리터럴은 `", "`(쉼표+공백)** — `prompts-summary-complete.ts:34` |
| **공백으로 둘러싼** `/` | `a / b` 는 쪼개지고 **`a/b` 는 안 쪼개진다** |

부재 표기 `없음` `없다` `해당 없음` `불필요` `none` `n/a` `null` `-`~`---` 는 **빈 목록으로 흡수**된다(`isEmptyMarker` `:147-150`).

> ★ `허용답(B): foreseeable/expected` (공백 없는 슬래시)는 **한 덩어리 문자열로 저장되고 게이트도 통과한다**(프로브 E3'). 그 문자열을 통째로 쓴 학생만 만점 — 사실상 죽은 허용답이다. 구분자는 반드시 `", "`.

### 3-5. 라벨 귀속 규칙 (★ 채점 사고의 진원지)

우선순위: **① 머리표 라벨 → ② 값 선두 라벨 → ③ 도착 순서 폴백** (`:180-198, 276-291`)

```ts
const VALUE_LEADING_LABEL_RE = /^[(（[]\s*([A-Za-z])\s*[)）\]]\s*/;   // :133
// answer: const target = label || leadingValueLabel(cell);          // :189
```

- `정답: (B) vulnerability` / `정답: (A) untrained` → **값 라벨로 귀속**해 (A)/(B) 가 뒤바뀌지 않는다(프로브 E4).
- 라벨이 **어디에도 없으면** 도착 순서로 미사용 라벨에 귀속(`:276-281`). `정답:` 두 줄이면 (A),(B) 순(프로브 P7-9). **동작은 하지만 쓰지 마라** — 순서를 한 번 흐트러뜨리면 EXACT 채점이 조용히 뒤바뀐다.
- 라벨 없는 `허용답:` 은 **정답이 있는 자리에만** 귀속된다(`:282-291`) — 유령 빈칸 방지.

## 7. 함정 (전부 코드 근거 있음 · ★는 프로브로 실증)

1. ★ **한 파일에 문항을 2개 이상 넣으면 앞 문항이 통째로 사라진다.** 이 파서는 **마지막 매치가 이긴다**(`parser-summary-complete.ts:181-198`). 게이트는 CLEAN 을 주므로 **아무도 모르게 4문항이 증발**한다(프로브 E13/E13'). **00-contract §3 의 「첫 매치」 서술이 이 유형에는 반대로 적용된다.**
2. ★ **`오답:` 블록을 쓰지 마라.** 이 유형에 없는 머리표라 파서가 인식하지 않고, `해설:` 뒤에 있으면 **해설 본문으로 통째 흡수**되어 학생 표면에 인쇄된다(프로브 P7-2). 객관식 골격을 복사해 오는 최다 사고 지점.
3. ★ **`모범답안:` 줄을 쓰지 마라.** `해설:` 앞이면 **조용히 폐기**되고(프로브 P7-3) 뒤면 해설을 오염시킨다. `정답(X):` 줄이 유일 진실원이며 `correctAnswer` 는 코드가 만든다(`prompts-summary-complete.ts:15-17`).
4. ★ **정답 값에 대안을 나열하면 아무도 못 맞힌다.** 슬래시·쉼표·세미콜론·`(or …)`·`or`·`또는` 전부 반려(`gate-summary-complete.ts:150-163`, 프로브 E3 5종). 동치는 **반드시 `허용답(X):` 로**. 반대로 **하이픈(`risk-blind`)·아포스트로피(`others' exposure`)는 안전**하다(픽스처 `:648-662`).
5. ★ **허용답 구분자는 `", "` 뿐이다.** `a/b`(공백 없는 슬래시)는 분해되지 않고 **한 덩어리로 굳어 게이트도 통과**한다(프로브 E3') — 그 허용답은 죽는다. `a / b`(공백 포함)·세미콜론·전각 쉼표는 분해된다.
6. ★ **값에 파이프(`|`)를 넣지 마라.** `firstCell` 이 뒤를 통째로 버리고 **게이트는 클린**이다(프로브 P7-7). 한국어 뜻풀이를 파이프로 붙이면 무음으로 사라진다.
7. ★ **인용 부호 `>` 는 흡수되지 않는다.** `> 요약문:` 은 줄 전체 유실 → 「요약문 누락」(프로브 E1'). 다른 md 유형(SUMMARY_COMPLETE_MC 등)은 `>` 를 흡수하므로 **유형별 관용 차이를 계약으로 착각하면 여기서 터진다**.
8. ★ **요약문은 반드시 한 줄.** 개행하면 둘째 줄이 조용히 사라진다(`pending` 은 1줄만 먹는다 — `:268-272`, 프로브 P7-1).
9. ★ **값에 다른 칸의 라벨을 붙이면 반려.** `정답(A): (B) vulnerability` 는 스냅이 **일부러 지우지 않고** 게이트가 자리를 지목한다(`:333-355`, `gate:123-127`). 전각 `（B）` 도 잡힌다. 반면 **자기 라벨 재부착(`정답(A): (A) untrained`)은 스냅이 벗긴다**(경고는 남는다).
10. ★ **요약문에 정답을 노출하지 마라.** 4자 이상 정답이 요약문 부분문자열이면 반려(`gate:278-285`). 허용답도 같은 검사를 받는다(`:327-329`).
11. ★ **정답이 지문 문장의 통째 복사면 반려.** 내용토큰(≥4자) **2개 이상이 전부** 지문에 연속으로 있으면 걸린다(`gate:93-106`). 즉 `conceivable hazard` 같은 2단어 축자 인용이 바로 반려다. **1단어 정답이 지문 어휘와 겹치는 것은 정상**(임계에서 제외).
12. ★ **요약문이 지문과 연속 8단어 겹치면 실격.** 토큰은 소문자·영숫자만 남기고 비교하므로 구두점 바꿔치기로는 못 피한다(`gate:47-53, 66-81`). 요약문은 **재진술**이지 발췌가 아니다.
13. ★ **라벨 뒤에 밑줄 `_____` 을 붙이지 마라.** 라벨 **직후**면 스냅이 지우지만 `AUTOSNAP` 경고가 남고, 라벨과 **떨어져 있으면 반려**된다(프로브 E6/E6'). 밑줄은 표시 계층이 붙인다(`summary-complete-mc.ts:215-221`).
14. ★ **`settings` 키는 `blankCount` 다.** `summaryCompleteBlankCount` 로 쓰면 **조용히 무시**되고 2칸으로 채점되어 3칸 문항이 「설정 범위 밖 빈칸 라벨 (C)」로 전량 반려된다(프로브 P6).
15. ★ **유닛 내 빈칸 정답 값이 한 칸이라도 겹치면 유닛이 통째로 차단된다.** `diversityTargets` 가 `blanks[].answer` 전량(`lane-summary-complete.ts:173-187` + `qgen-core.ts:345-363`). **5문항×2칸 = 서로 다른 10개 값**이 필요하다(프로브 P4).
16. ★ **정답에 원문자 `①` 을 쓰지 마라.** 이 유형의 정답 축은 **영어 문자열**이다 → 「값이 영어가 아님」(프로브 E7). MC 골격에서 복사해 오면 바로 죽는다.
17. **정답·허용답은 5단어 이하.** 초과 시 「{n}단어로 김」(`gate:34, 131-136`). 권장은 1~3단어(`prompts:166`).
18. **요약문은 8~60단어·한 문장·종결부호 필수.** 세미콜론·대시로 잇는 것은 안전하지만 **마침표 뒤 대문자가 오면 두 문장으로 센다**(`gate:55-64`).
19. **해설은 한국어 필수.** 한글이 한 글자도 없으면 반려(`gate:345-347`). 영어 인용은 따옴표 안에만, 12자 이상 인용은 지문·문항에 실재해야 한다(`explanation-quoted-tokens.ts`).
20. **허용답에 자신 없으면 줄 자체를 쓰지 마라.** `허용답(A):`(빈 값)·`없음`·`none` 은 파서가 빈 목록으로 흡수하지만(`:147-159`), **`허용답:` 에 적힌 것은 무조건 만점**이라는 사실이 본질이다(`adapter:23-25`). 의미장이 조금이라도 다르면 넣지 마라.
21. **불릿 뒤에는 공백을 넣어라.** `-정답(A):` 처럼 붙이면 장식 제거가 걸리지 않아 줄이 사라진다(`:107`). 애초에 **장식 0** 이 저작 규칙이다.
22. **지문을 md 본문에 다시 적지 마라.** 헤딩(`## 지문`) 없이 붙이면 **해설로 흡수**된다(프로브 P7-8, E14).
23. **라벨 없는 `정답:` 을 쓰지 마라.** 도착 순서 폴백이 동작해 게이트는 통과하지만(프로브 P7-9), 줄 순서를 한 번 흐트러뜨리면 EXACT 채점이 **조용히 뒤바뀐다**(되돌릴 수 없음).

## 8. 출제 포인트 다각화 축

> 한 지문에서 이 유형으로 5~8문항을 만들 때, **무엇을 달리해야 "N개 문항"이 되는가**.
> **이 유형에는 선지가 없다.** 헌법 §3 의 오답 택소노미(L1~L7 / F1~F7)를 선지에 배치할 자리가 없으므로, 그 부담이 전부 **요약문 슬롯 설계**와 **허용답 경계선**으로 옮겨온다.

### 8-A. 하드 제약 — 이것이 다각화를 강제한다

`ANSWER_DUPLICATE` 가 **빈칸 정답 값 전량**을 유닛 범위에서 유일하게 만든다(`lane-summary-complete.ts:173-187` + `qgen-core.ts:345-363`, 정규화는 소문자+영숫자). **문항 간에 정답 값이 한 칸도 겹칠 수 없다.** `POINT_DUPLICATE` 는 `point:` 문자열 중복을 차단한다.

| 유닛 구성 | 필요한 서로 다른 정답 값 수 | 실무 판단 |
|---|---|---|
| 5문항 × 2칸 | **10** | 110단어 이상 지문이면 여유. 프로브가 158단어로 통과 |
| 8문항 × 2칸 | **16** | 150단어 이상 권장 |
| 5문항 × 3칸 | **15** | 요약문이 세 겹 사슬을 견뎌야 하므로 논지가 3단 이상인 지문 필요 |

### 8-C. 설계로 달라지는 축 (교육적 판단 — 여기가 진짜 승부처)

1. **요약문이 겨냥하는 논지 위치** — 같은 지문이라도 요약의 초점을 어디에 두느냐로 문항이 갈린다.
   `① 도입 통념` / `② 개념·모형 정의` / `③ 핵심 기제(인과)` / `④ 유추·사례` / `⑤ 반증·조건` / `⑥ 결론·경고` / `⑦ 필연성·범위 진술`.
   프로브 5문항이 각각 ⑥·②·③·④·⑦ 을 겨냥한다. **한 지문에서 7문항까지 이 축만으로 확보된다.**

2. **★ 빈칸의 문법 슬롯 — 이 유형에서만 1순위 축이다.**
   선지가 없으므로 **슬롯이 답을 수렴시키는 유일한 장치**다. 슬롯을 바꾸면 동원되는 언어 지식 자체가 바뀐다.

   | 슬롯 | 요약문 표면 | 답이 구속되는 방식 |
   |---|---|---|
   | 명사 자리 | `becomes a source of (B).` | 관사·전치사가 가산/불가산·추상명사를 강제 |
   | 형용사 자리 | `a wholly (B) reading` | 한정사+명사 사이라 형용사만 가능 |
   | 서술 형용사(수동 결과) | `is left (A)` / `feels merely (B)` | 상태 서술만 가능, 극성이 문맥으로 고정 |
   | **3인칭 단수 현재 동사** | `a performance quietly (A) the pattern` | 목적어가 타동사를 강제, `-s` 가 어형까지 고정 |
   | 분사 수식 | `a listener left (A) in judgment` | 능·수동이 고정 |
   | 동명사·명사화 | `this small (C) produces` | 행위의 명사화만 가능 |

   **한 유닛에서 슬롯을 반복하지 마라.** 슬롯이 같으면 요약문이 달라도 학생이 하는 언어 작업은 같다.

3. **두 칸(이상)의 논리 관계** — 무엇으로 묶는가에 따라 추론의 **종류**가 바뀐다.
   원인–결과 / 문제–해결 / 대조–귀결 / 수단–목적 / 조건–결과 / **자유–필연**(무엇이든 되지만 없어서는 안 됨) / 전제–파생 / 행위–감지–정서(3칸 사슬).
   프로브 문항 5가 「자유–필연」축 — 같은 문장군을 쓰면서도 다른 인지 작업이 된다.

4. **정답의 추상화 층위** (`prompts-summary-complete.ts:70-85` 3분기가 이 축이다)
   지문 어휘의 1단계 일반화(BASIC) / 상위 개념으로의 번역(INTERMEDIATE) / **지문에 그 단어가 아예 없는 재개념화**(KILLER).
   ★ 게이트가 강제하는 하한이 있다: 내용토큰 2개 이상이 지문에 연속으로 있으면 반려(`gate:93-106`). 즉 **다단어 정답을 쓸수록 추상화를 강하게 해야 한다.**

5. **★ 허용답 폭 — 이 유형 고유의 축.** 같은 정답이라도 허용답을 몇 개 여느냐가 문항의 성격을 바꾼다.

   | 폭 | 성격 | 언제 |
   |---|---|---|
   | **0개** | 순수 EXACT — 슬롯이 답을 완전히 구속할 때만 정당하다 | 고유 개념어·문맥이 어형까지 고정하는 자리 |
   | **1개** | 표준 — 같은 의미축·같은 품사의 동치 1개 | 대부분의 KILLER |
   | **2~3개** | 관용형 — 어형 변형·축약형이 자연스러운 자리 | BASIC, 어휘 대역이 넓은 명사 자리 |

   **경계선 자체가 출제 의도다.** `unpracticed` 는 넣고 `unaware` 는 넣지 않는 판단(의미축이 다르다)이 곧 그 문항이 무엇을 묻는지의 선언이다(`prompts:61`).

6. **학생 오답 기제(선지가 없으니 「무엇을 써서 틀리는가」)** — 문항마다 다른 기제를 겨냥한다(`prompts:91-95`, 헌법 §3 의 F 코드 대응).

   | 기제 | 헌법 코드 | 이 유형에서의 형태 |
   |---|---|---|
   | 지문 표면어 그대로 옮겨 쓰기 | L1 + F5 | 정답을 상위 개념으로 올려 무력화 |
   | 인과 방향 반전(원인 자리에 결과어) | F1/F4 | 요약문의 접속 구조로 방향을 명시 |
   | 범위 확대(부분 사례 → 전체 결론) | F3 | 한정어를 요약문에 남겨 둠 |
   | 정도·극성 어긋남(같은 의미장, 다른 강도) | F7 | 허용답 경계선이 그 판정선 |

   **한 자리에서 최소 둘이 실제로 떠오르지 않으면 그 자리는 빈칸으로 쓰지 마라**(`prompts:94`).

7. **요약문의 통사 구조** — 종속절 선행(`Because …, …`) / 양보–전환(`Although …, …`) / 조건(`If …, …`) / 시간 순서(`first …, and only then …`) / 이유 후치(`…, since …`) / 병렬 3항(`stores …, notices …, and lets …`).
   구조가 바뀌면 빈칸이 앉는 자리와 학생의 독해 경로가 바뀐다. 3칸 이상은 병렬 3항 구조가 자연스럽다.

8. **난이도 배분** — 헌법 §4: 5문항 = BASIC 1 / INTERMEDIATE 2 / KILLER 2, 8문항 = 2/3/3. ★ 게이트가 난이도를 안 보므로 **이 축은 전적으로 저작·검수 책임**이다.
